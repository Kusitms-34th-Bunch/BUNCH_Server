# #23 이미지·Photo 기반 구현 계획

- 기준: 이슈 #23, [번들 Spec](../specs/bundle.md), [번들 구현 계획](bundle-implementation.md), [PRD](../PRD.md).
- 범위: 공용 ImageAsset, Photo·공동 업로더, 기존 프로필 이전, 참조 보호와 커밋 후 삭제.
- 유지 동작: 기존 imageUrl과 null 기본 이미지, JPEG 정사각·용량·메타데이터 검증,
  이미지 저장 실패 시 가입 완료, 번치 이미지 변경 실패 시 기존 이미지 유지, 권한 재검사.
- 먼저 기존 가입·본인 프로필·번치 이미지·초대 회귀 테스트를 실행한다.
- 새 V5에서 기존 식별자/URL 쌍과 충돌을 검사하고 백필한 뒤 기존 컬럼을 제거한다.
- 프로필 영속성을 nullable FK로 바꾸고 응답은 ImageAsset URL을 사용한다.
- 자산 삭제는 원 트랜잭션 성공 후 별도 트랜잭션에서 수행한다. 모든 참조 FK가 삭제를
  보호하며 자산 행 삭제 커밋 후 외부 파일 삭제를 시도한다. 실패는 식별자만 기록한다.
- 사진함 HTTP API는 만들지 않고 Photo의 소속·상태·잠금 조회 및 최종 삭제 연결 계약을 제공한다.
- 검증: 독립 PostgreSQL 테스트 DB의 Flyway 이전/재실행/불일치 거부, JPA validate,
  공동 업로더/해시 유일성, 타 번치 참조 거부, 공유 파일/롤백/삭제 실패/기존 API 회귀,
  최종 clean build. 사진함 실제 API와 iOS/WebView는 준비되지 않은 별도 수동 연동 범위다.
- 새 의존성·정리 배치·재시도 큐·bundle 선행 테이블은 추가하지 않는다.

- 최종 최소 변경 점검: 호출·문서 계약이 없는 `findByPhotoIdAndMemberId` 선언만 삭제한다.
  사용 중인 조회·잠금 경로의 동작은 유지하고 기존 Photo 통합 테스트와 전체 build로 회귀를 확인한다.
