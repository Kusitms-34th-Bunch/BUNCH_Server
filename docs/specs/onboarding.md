# 번치 온보딩·초대 Spec

이슈 #5의 확정 정책과 API는 [로그인·온보딩 API 계약](login-onboarding-api.md)을 따른다.
아래 미결정 목록은 원문 추적이며, 계약에서 확정한 항목은 해당 계약이 우선한다.

## 범위와 상태

기준 자료는 「BUNCH 상세 기능명세서 — 로그인·온보딩」(원본 파일명
`BUNCH_기능명세서_로그인온보딩.md`) 전체 중 2장이다. 36개 원문 기능을
[추적표](#onboarding-traceability)에 보존한다. 로그인·약관·개인 프로필·가입 완료와
기기 초대 정보의 보관/삭제는 [인증 Spec](auth.md)이 담당한다.

**요구사항**은 원문의 목표 동작, **제안**은 원문에서 제안·협의·조건부로 표시한 사항,
**미결정**은 원문 충돌이나 아직 정하지 않은 계약이다. 어느 표기도 구현 완료를 뜻하지
않는다. 이슈 #5는 번치 생성·Membership·초대 발급/조회/참여의 서버 기능을 추가한다.
공개 웹 화면은 별도 범위이며 공개 카드 API만 제공한다. 아래 입력·출력은 원문 의미를
보존하며 확정 HTTP 경로·DTO·저장 계약은 연결된 API 계약을 따른다.

## 번치 시작 선택 — 2.1.1~2.1.3

가입 완료 후 초대가 없거나 앱 실행 시 소속 번치가 0개이면 진입한다. 화면 진입 자체로
서버를 호출하지 않는다. 「본격적으로 / 번치를 시작해볼까요?」 아래에 카드 전체가
눌리는 `CreateBunchCard` 2개를 표시한다.

- 「새 번치 만들기」 → 생성 1단계. 친구 초대·함께한 순간 기록을 안내한다.
- 「초대받은 번치 참여하기」 → 링크 입력. 참여하여 함께 기록할 수 있음을 안내한다.
- 빠른 중복 탭은 첫 탭만 처리하여 화면이 두 번 열리지 않게 한다.

헤더 X는 [생성 중단 모달](#onboarding-create-cancel)(원문 2.2.11)을 거쳐 홈의 피드 탭으로
이동한다. **개인 프로필까지 완료한 회원은 소속 번치가 0개여도 공개 번치의 공개 번들을
볼 수 있다.** 팔로우 번치가 없으므로 팔로잉 구간 없이 전체 공개 구간만 표시한다.
백엔드는 가입 완료 회원의 해당 피드 요청을 허용하고 가입 중 회원은 거부한다.
다음 앱 실행에도 소속 번치가 0개이면 시작 선택을 다시 보여준다. 아직 만들기를 시작하지
않은 화면에서 재사용하는 모달의 「계속 만들기」 문구/복귀 상태는 추가 정리가 필요하다.

## 생성 3단계와 임시 상태 — 2.2.1

기본 정보 → 소개 → 분위기 순서다. `StepperItem` 3칸 중 현재만 보라색, 나머지는 회색이다.
제목은 「어떤 번치를 만들까요?」, 「번치를 소개해주세요」,
「우리 번치는 어떤 분위기인가요?」다. 단계 이동 중 모든 입력값을 유지한다.

헤더 뒤로가기와 iOS 스와이프 뒤로가기는 모든 단계에서 중단 모달을 연다. 이전 단계는
하단 「이전」으로만 이동한다. 앱에서 하나의 임시 상태를 관리하고 마지막 생성 요청에
한 번에 저장한다. 중간 서버 호출은 이름 중복 확인뿐이며 중간 저장은 없다.
앱 종료 시 초안은 보존하지 않고 다음에 처음부터 시작한다.

## 1단계 이름·공개 범위 — 2.2.2~2.2.5

### 이름 입력과 확인

「번치 이름」 입력란은 placeholder와 `n/12`를 표시한다. 1~12자이며 공백도 1자로 센다.
한글·영문 대소문자·**숫자·공백을 허용**하고 특수문자·이모지·줄바꿈은 허용하지 않는다.
앞뒤 공백은 저장 시 제거하고 공백만 있으면 0자로 본다. 12자 이후 일반 입력을 막고,
붙여넣기에서는 금지 문자를 제거하고 12자를 넘으면 앞 12자만 넣는다.

원문 2.2.2의 오류 문구 「특수문자와 숫자를 제외한 영문, 한글만 사용할 수 있어요.」는
숫자 허용 규칙과 충돌하는 **문구 오기**다. 숫자는 허용한다는 요구를 유지하되 최종 오류
문구는 디자인/기획 확정 대기로 남긴다. 소개 입력(다음 절)은 이름과 다른 문자 규칙이다.

입력 정지 0.5초 후 앞뒤 공백을 제거한 이름으로 전체 번치 중복 여부를 조회한다.
대소문자를 구분하고 내부 공백도 비교한다(`Bunch` ≠ `bunch`). 사용 가능/이미 사용 중
결과를 표시하며 확인 중·중복이면 「다음」을 비활성화한다.

**이름 중복 조회 실패는 개인 닉네임 확인 실패와 다르다.** 원문상 결과 문구 없이
「다음」을 활성화하고 생성 시 서버가 최종 판단한다. 이는 다른 기본 유효성·공개 범위
선택까지 면제한다는 뜻은 아니다. 확인 뒤 이름이 선점되면 생성 실패 규칙을 따른다.
유니코드 정규화 등 이름의 구체적인 동일성 계약은 닉네임과 일치시킬 범위를 정해야 한다.

### 공개 범위와 다음

`VisibilityOption`은 카드 전체가 눌리고 둘 중 하나만 선택한다. 초기 선택은 없다.
비공개는 자물쇠·팔로우를 승인한 번치만 기록 조회, 공개는 지구·누구나 기록 조회로 안내한다.
선택 카드는 Selected 회색 배경이며 다른 카드를 누르면 선택을 바꾼다.
원문 값은 `PUBLIC / PRIVATE`이고 생성 때 저장하며 이후 관리자만 번치 관리에서 변경한다.

처음 「다음」은 Disabled다. 유효한 1자 이상 이름·중복 아님·공개 범위 선택 시 활성화하여
소개 단계로 이동한다. 중복 조회 네트워크 실패 시에는 앞 절의 예외를 적용한다.
번치 공개 범위와 각 번들의 공개 범위가 별개라는 점은 0개 번치 공개 피드 규칙에도 적용한다.

<a id="onboarding-intro"></a>
## 2단계 필수 한 줄 소개 — 2.2.6~2.2.8

소개는 **필수 1~50자**이며 번치 홈·초대 화면에 이름과 함께 표시한다. 모든 문자,
숫자·특수문자·이모지·공백과 줄바꿈을 허용한다. 화면에 보이는 글자 기준으로
이모지·공백·줄바꿈 각각 1자이며 `n/50`를 갱신한다. 줄바꿈에 따라 입력란 높이도 늘어난다.
50자 이후 입력을 막고 초과 붙여넣기는 앞 50자만 반영한다. 공백·줄바꿈만 있으면 빈 값으로
보고 「다음」을 끈다. 저장할 때 앞뒤 공백·빈 줄을 제거하고 내부 줄바꿈은 보존하며
홈/초대에서도 살려 표시한다. 백엔드도 1~50자와 빈 값 여부를 검사한다.

`TIP` 배지와 「이런 소개는 어때요?」 아래 회색 박스에 고정 예시 3개(웃음이 끊이지 않는
모임, 맛집 탐방 모임, 일상을 기록하는 사이)를 항상 표시한다. 정보 표시일 뿐 탭해도
입력란에 들어가지 않는다. 고정 문구는 앱이 관리하고 별도 서버 입출력은 없다.

하단 「이전」은 항상 활성이고 1단계로 돌아가도 이름·공개 범위·소개를 유지한다.
「다음」은 처음 비활성, 공백/줄바꿈 이외 글자가 하나 이상이고 길이 규칙을 충족하면
활성화하여 분위기로 이동한다. '한 줄'이라는 이름 때문에 줄바꿈을 금지하지 않는다.

<a id="onboarding-atmosphere"></a>
## 3단계 분위기·뭉치 — 2.2.9

분위기 카드 4개를 2열×2행으로 표시한다. 그래픽·분위기 이름·설명은 디자인 진행 중이다.
카드마다 서로 다른 뭉치 유형 1종과 1:1 대응하고 번치당 하나만 선택한다. 초기 선택은
없으며 선택 카드는 Selected, 다른 카드 탭 시 선택을 바꾼다. 이미지 로딩 실패는 회색
자리표시로 대체하고 선택을 허용한다. 하나를 골라야 「번치 만들기」가 활성화된다.

뭉치 유형은 생성 시 저장하며 **생성 후 분위기/유형 변경 기능은 없다.** 화면의 뭉치는
유형과 발행 번들 수로 계산한 단계의 조합이다. 유형별 단계 이미지가 필요하며 생성 직후
번들 0개는 1단계다. 단계는 따로 저장하지 않는다. 원문의 `TYPE_1~TYPE_4`는 **예시**이며
확정 enum/DB schema가 아니다. 번치 프로필 사진 변경은 뭉치 유형 변경과 다르다.

<a id="onboarding-create"></a>
## 생성 요청과 원자성 — 2.2.10

「이전」은 항상 활성으로 소개 단계로 돌아가며 입력을 유지한다. 「번치 만들기」는 선택
완료 후 활성화되고 탭하면 로딩·중복 탭 차단, 성공하면 완료 화면으로 이동한다.
성공 뒤 생성 단계로 돌아가지 않는다.

| 의미상 입력 | 서버 검증·처리 | 의미상 출력 |
| --- | --- | --- |
| 이름·공개 범위·필수 소개·뭉치 유형·요청 키(Idempotency Key) | 가입 완료, 소속 번치 10개 미만, 이름 1~12자/허용 문자/전역 유일성(대소문자 구분), 소개 1~50자/빈 값 거부, 공개 범위·유형 유효성 | 생성 번치의 ID·이름·뭉치 유형·프로필 이미지 |

번치와 생성자의 활성 Membership을 한 트랜잭션으로 만들고 하나라도 실패하면 모두
되돌린다. 생성자는 첫 관리자이며 가입일·관리자 권한 받은 시각을 기록한다.
프로필 사진 업로드 전에는 선택한 뭉치 기본 이미지를 쓰고 마지막 사용 번치를 새 번치로
갱신한다. 같은 요청 키 재요청은 최초 번치를 반환하며 중복 생성하지 않는다.

- 이름 선점: 1단계로 돌아가 이름 아래 「이미 사용 중인 번치 이름이에요」 표시.
- 소속 10개 도달: 생성하지 않고 「참여할 수 있는 번치는 최대 10개예요.」 표시.
- 네트워크/서버 오류: 「번치를 만들지 못했어요. 다시 시도해 주세요」, 입력 유지,
  **같은 요청 키**로 재시도.
- 연타·응답 지연 후 재시도에도 번치는 1개만 생성되어야 한다.

요청 키 헤더/본문 위치·생성 주체·유효기간·동일 키 다른 입력 처리와 경합 시 한도 보장
방법, 실제 endpoint·트랜잭션/DB 제약 설계는 미결정이다.

<a id="onboarding-create-cancel"></a>
## 생성 중단 — 2.2.11

어느 단계에서든 헤더/스와이프 뒤로가기는 `Dialog` SolidButton 모달을 연다.
제목은 「번치 만들기를 그만둘까요?」이며 입력이 사라지고 피드로 이동함을 안내한다.
「나가기」는 임시값을 모두 지우고 피드 탭으로, 「계속 만들기」는 모달만 닫고 단계·입력을
유지한다. 모달 바깥 탭으로는 닫히지 않는다. 생성 전이므로 서버에 남는 데이터가 없다.
시작 선택 X도 원문상 이 모달을 재사용한다.

<a id="onboarding-created"></a>
## 생성 완료와 번치 사진 — 2.3.1~2.3.4

생성 응답으로 원형 프로필 이미지(초기 뭉치)와 번치 이름·축하 문구를 표시하고 Confetti를
1회 재생한 뒤 정지 화면을 유지한다. 추가 서버 조회는 없다. 효과 로딩 실패는 효과 없이
화면을 표시하며 최대 12자 이름도 말줄임 없이 자동 줄바꿈한다. 헤더/뒤로가기는 없고
스와이프 뒤로가기도 막는다. 이미 번치가 생성된 상태다.

`InviteMemberCard` 전체 탭(누르는 동안 Selected=True)으로 멤버 초대로 이동한다.
「내 번치로 이동하기」는 새 번치 홈(번치 탭)으로 간다. 생성 시 이미 마지막 번치를
갱신했으므로 여기서 다시 저장하지 않는다. 홈은 멤버 1명인 빈 상태다. 번들 생성은
멤버 2명 이상이 필요하므로 초대를 다음 행동으로 안내한다(번치 홈/번들 명세 연계).

### 번치 프로필 사진 변경

기본 뭉치 이미지의 카메라 아이콘은 「앨범에서 사진 선택 / 기본 이미지 적용 / 취소」
바텀시트를 연다. 기본 이미지 중에는 초기화 항목을 숨긴다. 네이티브 사진 1장 선택 →
1:1·원형 가이드 확대/이동 편집의 「취소 / 완료」 → 완료 즉시 저장·이미지 갱신 순서다.
기본 이미지 적용도 즉시 저장한다. **개인 사진은 가입 완료 때, 번치 사진은 여기서 즉시
저장한다.** 프로필 사진을 바꿔도 번치 홈의 뭉치 자체는 바뀌지 않는다.

앱은 자르고 크기를 줄이며 위치 EXIF를 제거한다. 서버는 번치 관리자 권한을 검사한다.
원문 출력은 사진 URL이며 기본 사진이면 빈 값으로 앱이 뭉치 유형의 이미지를 표시한다.
빈 값의 실제 JSON 표현, 업로드 전송/저장 방식·형식·용량/해상도·압축/변환 기준·저장소는
미결정이다. 개인 사진의 허용 형식을 번치 사진에 자동 확정 적용하지 않는다.

저장 중 이미지 위 로딩을 표시한다. 실패 시 기존 사진을 유지하고
「사진을 바꾸지 못했어요. 다시 시도해 주세요」를 표시한다. 접근 거부 시
[사진 권한 안내](auth.md#auth-profile)를 따른다. 업로드 중 「내 번치로 이동하기」를
눌러도 화면은 이동하고 업로드는 계속한다.

## 초대 링크 발급·복사·공유 — 2.4.1~2.4.5

멤버 초대 화면은 헤더 X, 제목/설명, 읽기 전용 초대 링크 **전체**, 오른쪽 복사 아이콘,
「번치는 최대 8명까지 함께할 수 있어요.」 안내, 밑줄 「나중에 할게요」로 구성한다.
원문의 URL은 예시이며 실제 도메인/경로가 확정되었다는 뜻이 아니다.

화면 진입 시 번치 ID로 서버에 유효한 초대 링크 하나를 요청한다. 있으면 재사용하고
없거나 만료·폐기되었으면 새로 발급한다. **번치당 유효 링크 1개, 발급 후 7일 만료**가
요구사항이다. 발급 멤버를 기록하여 초대 카드의 From에 사용한다.
[PRD](../PRD.md)의 MEMBER-01·권한표에 따라 해당 번치의 **활성 멤버는 Owner·Member
모두 초대 링크를 생성·공유할 수 있다.** 서버가 요청자의 활성 Membership을 확인한다.
발급·폐기 endpoint와 폐기 API 세부 계약, 동시 발급 처리는 아직 정하지 않았다.

로딩 중 스켈레톤을 표시한다. 조회 실패 시 링크 영역에 「다시 불러오기」를 표시하고
복사 아이콘을 끈다. 재탭으로 재요청하며 「나중에 할게요」는 계속 사용 가능하다.

복사 아이콘은 링크 전체를 클립보드로 복사하고 성공하면 「초대 링크가 복사되었어요.」와
「공유」 토스트를 5초 표시한다(`Toast`, Icon=False, Button=True).
다시 복사하면 토스트와 5초 시간을 다시 시작한다. 로딩/조회 실패 중 복사는 불가능하다.
「공유」는 네이티브 공유 시트를 열고 초대 URL을 전달한다. 공유 시트만 닫으면 변화가 없다.

복사·공유 행동을 기록한다는 요구가 있다. 원문의 `invite_link_copied`(번치 ID·User ID),
`invite_link_shared`는 이벤트 **예시**이며 최종 이벤트명·수집 경로·schema는 미정이다.
공유 OG 제목/이미지는 [공개 웹](#onboarding-public-web)의 협의 항목이다.

「나중에 할게요」와 헤더 X는 모두 생성한 번치 홈으로 간다. 초대는 홈/번치 관리에서도
다시 가능하다. 이 화면을 닫는 것은 생성 취소나 번치 삭제가 아니다.

**발급자와 실제 공유자는 다를 수 있다.** 원문은 단일 링크를 재사용하고 발급자를 From으로
표시하지만, 다른 멤버가 공유할 때도 최초 발급자를 유지할지·표시를 바꿀지는 미결정이다.
실제 공유자를 링크만으로 식별할 수 있다고 가정하지 않는다.

## 링크 입력과 참여 가능성 확인 — 2.5.1~2.5.4

설치 후 연결 소실이나 링크로 앱이 열리지 않은 경우에도 수동 입력으로 참여할 수 있다.
헤더 뒤로가기는 참여 중단 모달, 제목은 「초대받은 번치에 참여해볼까요?」,
`TextField` Button variant는 직접 입력/「붙여넣기」를 제공한다.
진입 시 서버 호출은 없고, 「완료」는 입력 1자 이상이면 활성화된다.

네이티브는 **붙여넣기 버튼을 눌렀을 때만** 클립보드를 읽고 기존 값을 대체한다.
화면 진입 시 자동으로 읽지 않는다. 비어 있음·비텍스트·붙여넣기 권한 거부 시 아무것도
넣지 않는다. 원문은 iOS 16 이상에서 클립보드 읽기 시 시스템 붙여넣기 허용 팝업이
나올 수 있음을 전제로 한다. `UIPasteControl` 사용은 팝업 부담을 줄이기 위한 **검토 권장**이며
채택 결정이 아니다.

완료 탭 시 로딩·연타 차단 후 서버에 확인한다. 토큰 존재, 7일 만료/폐기, 번치 존재,
8명 미만, 이미 멤버인지, 소속 10개 미만을 확인한다는 원문 요구다. 성공 시 번치 이름·소개·
사진·초대한 사람 닉네임으로 초대장 로딩 단계에 간다. **Membership을 생성하지 않는다.**
실패하면 입력값을 유지한 채 현 화면에 토스트를 표시하고 수정·재시도한다.

없는 토큰 반복 입력은 서버가 제한한다. 「계정당 10분에 10회」는 원문의 **예시**이며
최종 횟수/기간/기준 키는 미정이다. 제한 시 「잠시 후 다시 시도해 주세요」를 표시한다.

### 공통 참여 오류와 안내

| 사유 | 앱 동작 |
| --- | --- |
| 형식 오류·없는 토큰·만료·폐기·삭제 번치 | 「유효하지 않은 링크입니다.」 |
| 번치 정원 8명 | 「최대 인원을 초과한 번치입니다.」 |
| 내 소속 번치 10개 | 「참여할 수 있는 번치는 최대 10개예요.」 |
| 이미 멤버 | 「이미 참여 중인 번치예요.」 후 해당 번치 홈; 중복 참여하지 않음 |
| 네트워크·서버·제한 등 | 「잠시 후 다시 시도해 주세요」 |

입력 화면 토스트는 완료 버튼 바로 위에 3초 표시한다. 서버는 사유, 앱은 문구를 담당한다.
원문의 `INVALID / FULL / ALREADY_MEMBER / LIMIT_EXCEEDED`는 요구 분류이며 확정된
서버 enum/HTTP 상태가 아니다. 존재하지 않는 링크와 만료를 화면에서 구분하지 않아
링크 존재 여부가 드러나지 않게 한다. 정원·소속 한도·이미 멤버 등 여러 조건이 겹칠 때의
서버 오류 우선순위는 미정이다.

**원문 충돌:** 2.5.3은 링크 확인 시 소속 10개를 차단하지만 2.7.2는 소속 10개여도
초대 확인 화면까지 보여주고 참여 버튼에서 차단한다. 수동 입력/외부 링크 경로 차이로
의도한 것인지, 공통 확인 API를 어떻게 나눌지 확정하지 않는다. [미결정 목록](#onboarding-open-questions) 참조.

## 초대장 로딩과 확인 — 2.6.1~2.6.2

중앙 봉투 일러스트가 `Bunch/Join/Motion-01~03` 순서로 열린다. 버튼은 없으며 데이터
로딩과 애니메이션 1회가 **모두 끝난 후** 확인 화면으로 이동한다. 데이터가 빨리 와도
애니메이션은 끝까지 표시한다. 수동 입력은 직전 확인 결과를 재사용하고 외부 링크는
이 단계에서 같은 의미의 확인 요청을 한다. 실제 조회 API 공용 여부는 미결정이다.

원문의 다음 복구 동작은 **제안**이다.

- 네트워크 실패 또는 10초 초과: 이전 화면 복귀 + 「잠시 후 다시 시도해 주세요」.
- 외부 링크가 참여 불가: 사유 토스트 후 소속 번치가 있으면 번치 홈, 없으면 시작 선택.

복귀할 이전 화면·홈 선정·재시도 방식은 확정하지 않는다. 이는 인증 직후 자동 참여 실패
시 시작 선택으로 가는 원문의 비제안 규칙과 구분한다.

확인 화면은 뒤로가기, 「초대받은 번치에 참여할까요?」, `InviteCard`에 이름·소개·프로필
이미지·「From. {초대한 사람 닉네임} 님」·참여 버튼을 표시한다. 멤버 수·번들 수·내부 사진은
보이지 않는다. 초대한 사람은 원문상 링크 발급 멤버이며 탈퇴/번치 이탈 시 From을 숨긴다.
소개가 빈 경우 소개 줄도 숨긴다. 이는 기존/예외 데이터 표시 규칙이며 **새 번치 생성의
소개 필수 조건을 선택으로 바꾸지 않는다.** 발급자/공유자 문제는 발급 절의 미결정과 같다.

<a id="onboarding-join"></a>
## 참여 확정·경합·완료 — 2.6.3, 2.6.5~2.6.6

참여 탭은 로딩하고 중복 탭을 막는다. 서버에 초대 토큰과 요청 키(Idempotency Key)를
보내며 인증 후 자동 참여도 **동일한 서버 검증/중복 방지 의미**를 사용한다.

1. 가입 완료 User, 초대 유효·미만료·미폐기, 번치 존재, 정원 8명 미만, 사용자 소속 10개
   미만, 기존 활성 Membership 없음 여부를 **참여 시점에 다시 확인**한다.
2. 활성 Membership을 Member 역할로 만들고 가입일을 기록하며 마지막 사용 번치를 갱신한다.
3. 기존 멤버 전원에게 새 멤버 알림을 생성한다(알림 세부 명세 범위).
4. 같은 요청의 중복·동시 요청에도 Membership은 하나만 생성한다. 정원·소속 한도도
   동시 참여에서 넘지 않아야 한다. 구체적인 트랜잭션/잠금·DB 제약은 후속 설계다.

성공하면 완료 화면으로 이동한다. 이미 멤버면 새 Membership 없이 안내 후 해당 홈으로 간다.
미리보기 중 정원이 차거나 링크 만료/폐기·삭제가 발생해도 공통 사유를 적용한다.
만료·정원·삭제·소속 10개 등 재시도로 해결되지 않는 사유는 참여 버튼을 비활성화한다.
네트워크 오류는 토스트 후 **같은 요청 키**로 재시도한다. 키 범위/수명·재전송 계약은 미정이다.

완료 화면은 참여 응답의 이름·사진으로 합류 축하/함께 기록 안내를 표시하고 Confetti를
1회 재생한 뒤 정지한다. 추가 서버 호출은 없다. 효과 실패는 정지 화면만 표시한다.
헤더 뒤로가기는 피드 탭, 「번치로 이동하기」는 참여한 번치 홈으로 간다. 이미 참여 완료이며
뒤로가기로 참여를 취소하지 않는다. 마지막 번치는 참여 처리 때 이미 저장되었다.

<a id="onboarding-join-cancel"></a>
## 참여 중단 — 2.5.5, 2.6.4

입력/확인 화면의 헤더 뒤로가기는 「번치 참여를 그만둘까요?」 모달을 연다.
참여하지 않고 피드로 이동함을 안내하고 「나가기 / 계속 참여하기」를 제공한다.
나가기는 참여 없이 피드 탭, 계속은 모달만 닫고 현재 화면/입력값을 유지한다.
입력 화면 중단은 서버에 남는 데이터가 없다.

초대 확인 화면에서 나갈 때는 서버 거절 데이터를 만들거나 발급자에게 거절 알림을
보내지 않으며 보관 중 기기 초대 정보를 삭제한다. 삭제 책임과 생명주기는
[인증의 기기 보관](auth.md#auth-invite-storage)을 따른다. 원문에 입력 화면(2.5.5)의
기기 초대 정보 삭제까지 명시된 것은 아니므로 그 적용 범위는 추가 확정이 필요하다.

<a id="onboarding-public-web"></a>
## 공개 웹 초대와 설치 후 복구 — 2.7.1

로그인 없는 모바일 웹 초대 확인은 원문상 **외부 웹으로 남는 유일한 제품 화면**이다.
앱 내부 WebView 화면을 일반 브라우저 서비스로 공개한다는 뜻이 아니다.
설치된 iPhone은 Universal Link로 바로 앱을 열고, 미설치는 같은 URL에서 웹 초대 카드를
표시한다. `apple-app-site-association`과 앱 연결 설정이 필요하나 도메인·경로는 미정이다.

웹은 앱 확인 화면(`Bunch/Join/Invitation`, `InviteCard`)과 같은 이름·소개·이미지·From·참여
버튼을 표시하고 왼쪽 위 뒤로가기를 두지 않는다. 참여 버튼은 **App Store BUNCH 앱
페이지로 이동**하며 웹에서 로그인·Membership 생성은 하지 않는다. 설치 후 원래 초대 링크
재클릭 또는 앱의 링크 붙여넣기로 이어간다.

백엔드는 토큰만으로 위 최소 정보만 비인증 조회 가능하게 해야 한다. 번치 내부 사진·번들·
멤버 수는 응답/화면에 노출하지 않는다. 앱과 공개 조회 API를 공유할 수 있다는 것은 원문의
허용안이며, 현재 로컬 보안 설정에 공개 초대 경로가 있다는 뜻은 아니다.

- 만료·폐기·삭제 링크: 번치 정보를 보이지 않고 「유효하지 않은 링크입니다.」 표시.
  무효 화면 디자인은 미정이다.
- 정원 8명: **웹에서는 정원을 확인/안내하지 않고 정상 카드 표시.** 앱의 확인/실제 참여에서
  차단한다. 공개 정보 조회에 인증 사용자의 소속 10개 판정을 요구하지 않는다.
- Kakao 등 인앱 브라우저 때문에 설치된 앱이 열리지 않아도 웹 카드와 App Store 이동을
  제공한다. 설치된 경우 App Store 「열기」를 쓸 수 있으며 초대 재전달 보장은 하지 않는다.
- Android/PC의 iPhone 앱 안내는 원문의 **제안**으로 강제 정책이 아니다.

설치 후 첫 실행에 맥락을 전달하는 Deferred Deep Link는 **구현 가능하면 적용하는 조건부
항목**이다. 설치 후 자동 복구를 확정 약속하지 않는다. 기본 복구는 링크 재클릭/붙여넣기다.
참여 클릭 측정은 요구되며 `web_invite_join_clicked`는 이벤트 예시다.
OG 「{번치 이름}에 초대받았어요」와 번치 프로필 이미지는 **협의/디자인 필요** 항목이다.

## 앱 링크 수신과 로그인 상태별 처리 — 2.7.2

네이티브가 링크를 받으면 [인증 Spec의 기기 초대 보관](auth.md#auth-invite-storage)에 따라
먼저 보관한다. 보관 TTL·로그아웃 삭제·여러 링크 제안은 그 절만을 기준으로 한다.
그 후 가입 상태별 처리 책임은 다음과 같다.

| 수신 당시 상태 | 목표 경로 |
| --- | --- |
| 비로그인·신규 | Entry → 약관 → 개인 프로필 → 가입 완료 → **확인 화면 재표시 없이 자동 참여** → 참여 완료 |
| 비로그인·기존 가입 완료 회원 | Entry → 로그인 성공 → 같은 자동 참여 → 참여 완료 |
| 가입 중(약관/프로필 미완료) | 미완료 단계 → 가입 완료 → 같은 자동 참여 |
| 이미 로그인·가입 완료 | 초대장 로딩 → 확인 카드 → 사용자의 「참여하기」 → 완료 |
| 이미 대상 번치 멤버 | 중복 참여 없이 대상 번치 홈 |

가입/로그인 과정에서는 참여하지 않는다. 필요한 가입 절차를 끝낸 후에만
[참여 검증](#onboarding-join)을 수행한다. 자동 참여 실패(진행 중 만료·정원 초과·번치 삭제
등)는 **가입 완료를 유지**하고 사유 토스트 후 번치 시작 선택으로 보낸다. 기존 회원의
로그인 후 자동 참여 실패 도착지는 별도 세부 규정이 없어 확정이 필요하다.

앱 사용 중 새 초대 링크가 열리면 현재 화면 위에 초대장 로딩부터 시작한다.
번치 생성 도중에도 동일하며 만들던 입력값은 버린다. 이는 일반 뒤로가기의 중단 모달과
다른 원문 예외다. 미로그인/가입 중 여러 링크의 최종 선택은 기기 보관의 제안 상태다.

소속 10개인 사람도 외부 링크에서는 확인 화면까지 보이고 참여 버튼에서 한도를 안내한다는
요구가 있다. 수동 확인의 선차단 규칙과의 충돌은 미해결이다. 단순 조회·미리보기에서는
Membership을 만들지 않으며 실제 참여에서 한도와 유효성을 반드시 재검사한다.
