# 번들 Spec

번들의 생성·공동 편집·추천·발행과 사진함 연동 규칙을 정의한다.
번들 기능은 이 문서를 기준으로 구현한다. 발행본 상세·수정은
[2026-11-07 일괄 저장 계약](published-bundle-edit.md)이 이전 개별 저장 계약보다 우선한다.
인증·가입 상태·번치 소속 검증은 [로그인·온보딩 API 계약](login-onboarding-api.md)을 따른다.

2026-11-10 #107은 최신 시트 4.3.3~4.3.14의 서버 계약을 반영한다.
[제목 CRDT](bundle-title-crdt.md), [typing/presence](bundle-realtime-107.md),
[장소 작업](bundle-locations.md)을 함께 따른다. 미전송 입력은 재연결 때 폐기한다.
2026-11-12 확정 계획으로 작업 프로필과 위치 동시 편집 규칙을 적용한다.
비독점 BEGIN/END 필드 editing은 아래 6절과 [presence 계약](bundle-realtime-107.md)을 따른다.
제목·코멘트는 실제 TYPE 입력만 표시하며 focus BEGIN과 픽 표시는 제외한다.
사진·위치의 이동 과정 실시간 공유(좌표 전송·상대 이동 애니메이션)는 후속 구현으로 둔다.
4.3.8 K41의 보관 문구는 4.3.14 J47/K47 및 기존 사용자 승인9번과 충돌하여 정렬 대기다.

## 1. 데이터와 상태

| 개념 | 규칙 |
| --- | --- |
| 이미지 자산 | 개인·번치 프로필, Photo, 발행 번들이 참조하는 저장 파일의 식별자·URL |
| Photo | 번치 사진함의 기록. 이미지 자산·촬영 정보·전체 업로더를 관리 |
| 번들 | 하나의 번치에 속하는 공동 게시물. 작성 중부터 발행까지 같은 번들로 관리 |
| 번들 사진 | Photo 연결, 순서, 추가자·시각, 캡션·수정자·수정 시각·버전을 관리 |
| 참여 멤버 | 번들을 함께 편집하는 현재 번치 멤버. 참여 시각을 기록 |
| 멤버별 코멘트 | 번들당 멤버별 1개. 작성자 본인만 편집 |
| 발행 기여자 | 발행 시점의 참여 멤버 |
| 추천 번들 | 사진함 사진을 묶어 제시하는 선택 후보 |

- 번들 상태는 `작성 중 → 발행 처리 중 → 발행됨`으로 전환한다. 발행 후 작성 중으로 되돌리지 않는다.
- 초안 폐기와 번들 삭제는 영구 삭제이며 복구할 수 없다.
- 사진함은 업로드·중복 병합·Photo·업로더·촬영 정보·이미지 파일을 관리한다.
- 번들은 사진 구성·순서·캡션·참여 멤버·코멘트·제목·위치·날짜·공개 범위·발행 상태를 관리한다.
- 사진 업로드와 번들 생성은 별개다. 사진함에 사진만 보관할 수 있다.
- Photo와 이미지 자산의 수명을 분리한다. 사진함에서 Photo를 지워도 발행본이 참조하는 파일은 유지한다.
- 개인·번치 프로필은 이미지 자산을 참조한다. 기본 이미지는 참조가 없는 상태이며 기존 API의 `imageUrl` 응답을 유지한다.
- 발행 시 참여 멤버 목록을 고정하여 기여 기록으로 사용한다. 이후 번치 소속 변경으로 발행 참여 목록을 제거하지 않는다.

## 2. 권한

모든 요청에서 가입 완료·이용 가능 계정, 현재 번치 소속, 하위 데이터의 번치 소속을 검증한다.
메인 관리자 `OWNER`(활성 1명), 공동 관리자 `CO_OWNER`, 일반 멤버 `MEMBER`와
번들 생성자·참여 여부를 별도로 판단한다. 아래 관리자는 OWNER와 CO_OWNER를 포함한다.

| 행동 | 권한 |
| --- | --- |
| 초안 생성·조회 | 현재 번치 멤버 |
| 제목·사진·순서·캡션·공개 범위·위치·날짜 편집 | 해당 초안의 참여 멤버 |
| 참여 멤버 추가 | 해당 초안의 참여 멤버 |
| 다른 참여 멤버 제외 | 초안 생성자 또는 해당 초안에 참여 중인 관리자 |
| 초안에서 스스로 나가기 | 해당 초안의 참여 멤버 |
| 본인 코멘트 작성·수정 | 본인 |
| 발행 | 초안 생성자 또는 해당 초안에 참여 중인 관리자 |
| 초안 폐기 | 초안 생성자 또는 해당 초안에 참여 중인 관리자 |
| 발행본의 공용 내용 수정·번들 삭제 | 현재 메인 관리자 OWNER만 |
| 발행본 코멘트·참여자 변경 | 누구도 불가 |

- 참여하지 않은 관리자는 초안을 볼 수만 있고 편집·발행·폐기할 수 없다.
- 참여하지 않은 멤버가 스스로 참여자로 등록하는 기능은 없다.
- 관리자도 타인의 코멘트를 수정·삭제·숨길 수 없다.
- 초안은 공개 범위와 관계없이 현재 번치 멤버에게만 보인다.
- 권한은 요청 처리 시점에 확인한다. 역할·참여 상태가 바뀌면 화면의 편집·발행 가능 여부도 갱신한다.
- 서버는 관리자 여부·생성자 여부·참여 여부를 각각 제공한다.

초안의 제목·공개 범위·날짜·캡션·사진 구성·순서 실제 변경과 본인 코멘트 실제 저장은
같은 트랜잭션에서 현재 소속의 `lastActivityAt`을 갱신한다. 발행 후 코멘트 저장은 허용하지 않는다.
생성·참여 변경·발행·공용 발행본 편집·동일 값·재생·실패·조회·편집권·presence는 제외한다.

## 3. 사진 선택과 초안 생성

관련 기능: `DRAFT-01`, `GROUP-02`, `GROUP-04`, `PHOTO-06`.

### 3.1. 사진 선택

- 번치 홈의 「+」와 「첫 번들 만들기」에서 같은 번들 만들기 화면으로 진입한다.
- 현재 사진함의 날짜 섹션·날짜 미확인 영역·멤버 필터를 사용한다.
- 사진은 고른 순서대로 번호를 매긴다. 선택 해제 시 뒤 번호를 당긴다.
- 필터를 바꿔도 숨겨진 사진의 선택·번호를 유지한다.
- 공동 업로드 사진은 업로더 각각의 필터에 포함하고 전체 장수는 한 장으로 센다.
- 다른 멤버의 사진, 날짜 미확인 사진, 다른 번들에 사용한 사진도 직접 선택할 수 있다.
- 사진은 1~20장 선택한다. 21번째 선택은 막는다.
- 선택하는 동안 서버에 초안을 저장하지 않는다. 뒤로가기로 나가면 선택을 버린다.
- 사진이 없으면 「아직 사진이 없어요.」와 「사진함에 사진을 올리면 번들을 만들 수 있어요.」를 표시한다.
- 이 화면에서는 업로드·촬영 날짜 변경·사진함 사진 삭제를 하지 않는다.

### 3.2. 초안 생성

- 「번들 만들기」를 눌러 생성한다. 선택 사진이 없으면 버튼을 비활성화한다.
- 사진함 선택 모드에서는 확인 모달의 「예」로 생성한다. 21장 이상이면 모달을 열지 않고 20장 제한을 안내한다.
- 번치의 활성 멤버가 2명 이상이어야 하며 번치당 작성 중인 초안은 최대 10개다.
- 최초 참여 멤버는 생성자와 선택 Photo의 현재 번치 소속 업로더 전체의 합집합이다.
- 생성자는 항상 포함한다. 참여 멤버가 생성자 1명뿐이어도 생성하지만 발행은 막는다.
- 선택 번호 순으로 사진을 저장하고 첫 사진을 대표 사진으로 사용한다.
- 직접 선택한 초안의 제목은 빈 값이다. 추천을 적용했으면 마지막 적용 후보 제목을 초기 제목으로 사용한다.
- 추천 적용 후 사진을 바꿔도 추천 생성 출처를 유지한다.
- 공개 범위·위치·날짜는 선택되지 않은 상태로 시작한다.
- 선택 사진이 하나라도 삭제되었거나 다른 번치 소속이면 생성 전체를 거부한다.
  앱은 사라진 사진을 선택에서 빼고 번호를 갱신한 뒤 사용자가 다시 생성하도록 한다.
- 생성자 외 참여자에게 참여 알림을 보내고, 사용 사진은 추천 계산에서 제외한다.
- 중복 요청은 같은 초안을 반환하며 참여 연결·알림을 중복 생성하지 않는다.
- 생성 실패 시 초안·사진 연결·참여 멤버를 함께 되돌린다.

## 4. 참여 멤버

관련 기능: `DRAFT-02`, `DRAFT-15`, `PHOTO-07`.

- 현재 번치 멤버만 추가한다. 추가된 멤버는 참여 목록 맨 뒤에 들어가고 알림을 받는다.
- 생성 뒤 사진을 추가해도 참여자는 자동 변경하지 않는다. 멤버 추가 기능으로 변경한다.
- 새 참여자도 코멘트를 작성해야 발행할 수 있다.
- 다른 사람이 생성자를 제외할 수 없다.
- 생성자 외 참여자는 스스로 나갈 수 있다. 참여자가 1명만 남으면 초안을 유지하고 발행을 막는다.
- 제외되거나 스스로 나간 멤버의 코멘트는 삭제한다. 추가한 사진·캡션·수정한 공용 내용은 유지한다.
- 타인에 의한 제외는 대상자에게 알린다. 스스로 나가면 제외 알림을 보내지 않는다.
- 참여에서 빠진 멤버의 편집 잠금·표시를 해제하고 보기 전용으로 전환한다.
- 생성자가 초안에서 스스로 나가면 해당 초안을 영구 삭제한다.
- 생성자가 번치를 나가거나 내보내지거나 회원 탈퇴하면 해당 생성자의 작성 중인 초안을 모두 삭제한다.
  생성자 권한을 넘기지 않는다.
- 다른 참여자가 번치를 나가거나 내보내지거나 탈퇴하면 초안 참여와 코멘트를 제거한다.
  해당 멤버의 사진은 11절에 따라 정리한다.
- 초안 삭제 시 사진 연결·캡션·코멘트·참여 연결·잠금을 함께 정리하고 사진함 원본은 유지한다.
- 삭제된 초안을 보고 있던 멤버에게 「삭제된 번들이에요」를 표시하고 이전 화면으로 이동한다.

## 5. 공동 편집

### 5.1. 제목·코멘트·캡션

관련 기능: `DRAFT-05`, `DRAFT-06`, `DRAFT-14`.

| 항목 | 제한 | 초안 | 발행 |
| --- | --- | --- | --- |
| 제목 | 최대 40자, 줄바꿈 불가, 이모지 허용 | 빈 값 허용 | 앞뒤 공백 제거 후 1자 이상 |
| 코멘트 | 최대 400자, 줄바꿈·이모지 허용 | 빈 값 허용 | 모든 참여자가 공백·줄바꿈 외 1자 이상 작성 |
| 캡션 | 최대 200자, 줄바꿈·이모지 허용 | 선택 | 선택 |

- 길이는 눈에 보이는 글자(grapheme)로 센다.
- 앱은 상한에서 추가 입력을 막고 초과 붙여넣기는 상한까지만 반영한다.
  제목 CRDT 병합 결과는 40자를 넘어도 자르지 않고 보존하며 발행만 차단한다.
  기존 문자열 제목 전환 API와 코멘트·캡션은 상한 초과를 거부한다.
- 제목의 앞뒤 공백을 제거한다. 공백만 있으면 빈 제목이다. 줄바꿈 붙여넣기는 앱에서 공백으로 바꾼다.
- 초안 코멘트는 본인만 수정·비우기를 할 수 있다. 발행 후에는 수정·비우기·삭제할 수 없다.
- 캡션은 번들 사진에 속한다. 같은 Photo라도 번들마다 별도 캡션을 가진다.
- 공동 편집 화면의 캡션은 최대 2줄로 표시하고 캡션 화면에서는 전체를 표시한다.

### 5.2. 사진 구성·순서

관련 기능: `DRAFT-03`, `DRAFT-04`, `DRAFT-14`.

- 번들 사진은 1~20장이고 같은 Photo를 중복 연결하지 않는다.
- 공동 편집의 사진을 누르면 캡션 화면으로, 캡션 화면의 사진을 누르면 크게 보기로 이동한다.
- 사진 추가·제거·순서 변경은 캡션 화면에서 수행한다.
- 추가 경로는 「번치 사진함에서 가져오기」와 「내 갤러리에서 가져오기」다.
- 사진함 선택 화면은 현재 번들 사진을 순서대로 선택한 상태로 연다.
- 적용 시 사용자가 추가·해제한 차이만 최신 구성에 반영한다.
  그사이 다른 멤버가 추가한 사진을 지우거나 제거한 사진을 복원하지 않는다.
- 기존 사진의 선택을 풀었다 다시 고르면 그 사진을 새 번호가 붙은 순서대로 뒤에 둔다.
  요청의 재선택 목록과 선택 순서를 사용하며 기존 사진 행·캡션을 보존한다.
  재선택하지 않은 사진의 최신 상대 순서는 유지하고, 그사이 삭제된 재선택은 복원하지 않는다.
- 병합 결과가 20장을 넘거나 0장이 되면 전체 변경을 거부한다.
- 갤러리 사진은 사진함에 업로드하고 성공한 Photo만 선택 순서대로 번들 뒤에 추가한다.
  형식·용량·한도·중복 병합은 사진함 규칙을 따른다.
- 일반 추가와 갤러리 추가는 서버 처리 순·요청 내 선택 순으로 남은 20장 정원까지만 수락한다.
  사진함 ‘적용’의 add/remove 병합은 초과하면 전체 거부한다. 2026-11-10 사용자 확인으로
  갤러리의 용량 경합도 부분 수락으로 확정했다. 업로드 자체의 성공·실패와 구분한다.
- 같은 사진의 서로 다른 위치 이동은 나중에 서버 처리한 이동을 최종 위치로 적용한다.
  같은 요청 ID의 재전송은 새 이동이 아니므로 뒤의 이동을 되돌리지 않는다.
- 업로드 성공 후 번들 연결이 실패해도 사진함 사진을 유지한다. 이미 번들에 있는 Photo는 다시 연결하지 않는다.
- 번들에서 사진을 빼면 캡션도 삭제하고 사진함 원본은 유지한다.
- 캡션이 없으면 바로 제거하고 캡션이 있으면 삭제 확인 후 제거한다.
- 마지막 1장은 직접 제거할 수 없다. 남은 2장을 동시에 제거해도 최종 1장을 유지한다.
- 순서는 드래그를 놓을 때 한 번 저장한다. 캡션과 편집 표시는 해당 사진을 따라간다.
- 드래그 시작만으로 사진의 편집권을 획득하지 않는다. 다른 멤버의 사진 보기·선택은 막지 않는다.
- 이동은 대상과 앞뒤 사진 ID의 의도를 최신 순서에 재적용한다. 기준 사이가
  비인접으로 바뀌어도 거부하지 않는다. 삭제된 기준은 저장한 이전 자리로 보정한다.
  대상 사진 삭제는 이동보다 우선하며 복원하지 않는다. 동일 틈의 서로 다른 이동은
  DB 잠금 획득 후 처리한 순서대로 배치한다.
- 첫 사진이 바뀌면 대표 사진도 바뀐다.
- 사진 제거·이동은 다른 사용자의 legacy lease로 막지 않는다. 캡션 전환은 #123 범위다.

### 5.3. 공개 범위

관련 기능: `DRAFT-07`.

- 「멤버 공개」와 「공개」 중 선택하며 초기 선택은 없다. 발행하려면 하나를 선택해야 한다.
- 한 번 선택하면 다른 값으로 바꿀 수 있지만 선택 해제는 할 수 없다.
- 「멤버 공개」는 현재 번치 멤버에게만 노출한다.
- 공개 번치의 「공개」는 전체 공개, 비공개 번치의 「공개」는 승인된 팔로워 번치 대상이다.
- 초안은 선택과 관계없이 현재 번치 멤버에게만 보인다.
- 실제 노출은 발행 상태와 번치·번들의 공개 범위를 함께 검증한다.

### 5.4. 위치·날짜

관련 기능: `DRAFT-17`, `DRAFT-18`.

- 위치·날짜는 선택 입력이며 최초에는 비어 있다. 초안 참여 멤버가 추가·변경·삭제할 수 있다.
- 위치는 최대 3개 목록이다. provider·장소명·주소·외부 ID·순서를 저장하고 좌표는 저장하지 않는다.
  2026-11-07 승인 계약은 [장소 목록 계약](bundle-locations.md)을 따른다.
  외부 검색 공급자 연동은 후속이며 이번에는 구조를 검증한 장소 입력을 받는다.
- 사진 촬영 위치·휴대폰 현재 위치·위치 권한을 사용하지 않는다.
- 장소 선택 시 즉시 저장하고 검색 취소 시 기존 장소를 유지한다.
- 번들 날짜는 사진함 촬영 날짜와 독립적이다. 미래 날짜는 허용하지 않는다.
- 날짜를 정하지 않았으면 유효 촬영 날짜 중 사진이 많은 순으로 최대 3개를 추천한다.
  동률이면 이른 날짜가 먼저이며 날짜 미확인 사진은 제외한다.
- 추천으로 생성한 초안은 후보의 첫날 날짜를 첫 칩으로 두고 나머지는 중복 없이 사진 수 순으로 채운다.
- 날짜 지정 전에는 사진 구성·촬영 날짜 변경에 따라 추천 칩을 갱신한다.
- 지정한 번들 날짜는 사진 변경으로 바꾸지 않는다. 날짜를 지우면 추천 칩을 다시 표시한다.
- 발행 후 위치·날짜는 현재 메인 관리자 OWNER만 변경할 수 있다.

## 6. 자동 저장·동시 편집

관련 기능: `DRAFT-08`, `DRAFT-09`, `DRAFT-10`, `DRAFT-12`.

- 제목·코멘트·캡션은 입력이 1초 멈추거나 입력 영역을 벗어나면 저장한다.
- 사진 구성·순서·참여 멤버·공개 범위·위치·날짜 변경은 즉시 저장한다.
- 한 기기의 같은 초안 저장 요청은 순차 처리한다.
- 서버 저장 완료 전에는 「저장 중」, 본인 보류 저장이 없으면 「저장 완료」를 표시한다.
  공동 편집 화면 헤더에 본인의 저장 상태만 표시한다.
- 제목·날짜·장소·사진 변경에는 사용자 독점 편집권이 필요 없다. 서버 내부 번치→번들
  DB 잠금과 매 요청 권한/상태 검증은 유지한다.
- 제목은 글자 단위 CRDT, 날짜는 마지막 저장값, 장소는 ID 작업, 사진은 이동 의도로
  병합한다. 전환용 전체 문자열/장소 목록 저장은 버전 검증을 유지한다.
- 사진은 추가 시트·사진함/갤러리 선택·업로드·삭제 확인·드래그 동안 「사진」 제목 옆에
  프로필을 모아 표시한다. 선택창이 닫혀도 업로드가 진행 중이면 유지한다.
- 위치 교체/드래그는 LOCATION:{bundleLocationId}로 위치 이름 바로 옆에, 신규 검색은
  LOCATION으로 「+ 위치 추가」 옆에 표시한다. 날짜는 선택 화면 동안 「날짜 추가」 옆에 표시한다.
  여러 작업자의 프로필을 모두 표시한다. 시트·화면·모달 종료 시 해당 작업을 즉시 해제한다.
- BEGIN은 DATE·LOCATION·PHOTOS·PHOTO:{bundlePhotoId}·LOCATION:{bundleLocationId}의
  실제 작업 생명주기에서 보낸다. 제목·코멘트 focus BEGIN은 호환 no-op이며 PICK BEGIN은 거부한다.
  항목 BEGIN은 양의 10진 정수 ID와 현재 초안 소속을 검증한다.
  연결당 target별로 관리하여 업로드와 다른 필드 작업이 겹쳐도 유지한다.
  편집 중인 각 target만 5초마다 갱신하고 마지막 BEGIN부터 15초에 만료한다.
  VIEW나 TYPE는 editing 기한을 연장하지 않는다. 갤러리 진입의 window blur는 앱 백그라운드와 구분한다.
- 제목/본인 코멘트의 실제 입력만 TYPE preview로 전달하며 3초 무입력 후 해제한다.
  BEGIN은 typing을 만들거나 연장하지 않고 비텍스트 필드에는 TYPE preview가 없다.
- END는 해당 연결의 지정 target editing·typing을 즉시 지우며 target 생략 시 모두 지운다.
  항목 END는 문법만 검증하므로 사진 행이 이미 삭제되어도 정리할 수 있다.
  BLUR/STOP도 target 지정 시 해당 작업만 해제하고 생략 시 모두 해제한다.
  LEAVE/BACKGROUND는 입장 상태까지 제거한다.
  disconnect 후 아직 유효한 editing은 `min(마지막 BEGIN, 마지막 연결 신호)+15초`에 만료한다.
  VIEW는 disconnect 후에도 editing을 연장하지 않는다. BEGIN 0초·VIEW/disconnect 10초이면
  editing은 15초, 입장은 25초에 만료한다. disconnect 시각부터 새로 세거나 끝난 editing을 부활시키지 않는다.
  기존 typing의 disconnect 유예는 [presence 계약](bundle-realtime-107.md)을 따른다.
- 여러 연결의 입장은 memberId, editing은 memberId/target으로 합친다. 한 연결의 종료가
  다른 연결의 유효 상태를 지우지 않는다. 발행·삭제·접근 상실은 관련 상태를 정리한다.
- presence/editing/typing은 revision·updatedAt·번치 활동을 바꾸지 않는다.
- 연결이 끊기면 읽기 전용과 「인터넷 연결을 확인해 주세요.」 배너를 표시한다.
  재연결 시 최신 snapshot을 새로 읽고 서버 미반영 수정은 폐기한다.
  서버에 저장된 변경은 응답이 유실돼도 snapshot에서 복구한다.
- 원격 변경은 열린 공동 편집 화면에 반영한다. 로컬 드래그 중 해당 목록의 원격 변경은
  드롭·취소까지 보류하고 이후 최신 결과로 맞춘다. 발행·삭제·권한 상실은 즉시 처리한다.
  손을 뗄 때 앞뒤 ID 이동을 1회 저장하며 취소는 저장하지 않는다.
  픽 화면은 재진입 때 갱신하며 #123이 소유한다.
- 최종 업로드 진입 시 현재 다른 멤버의 typing/editing이 있으면 「편집 중인 멤버가 있어요」
  안내를 띄운다. 표시만으로 발행을 차단하지 않으며 서버는 권한·필수 조건을 다시 검증한다.

### 6.1. 통신·저장 계약

- 내용 저장은 REST, 비독점 editing/typing/presence와 커밋 후 이벤트 전파는 기존 STOMP를 쓴다.
  presence data의 editing 배열은 `memberId/target/expiresAt`만 공개하며 잠금을 부여하지 않는다.
- 기존 CONNECT/frame/구독 JWT·Redis 세션·번치/참여 권한 검증을 유지한다.
- CRDT 상태와 표시 제목, 사진/장소 작업 결과는 같은 DB 트랜잭션에서 저장한다.
  AFTER_COMMIT 전달 실패는 저장 실패로 바꾸지 않으며 재진입 snapshot이 복구 기준이다.
- envelope는 `type / bunchId / bundleId / revision / requestId / data`다.
  비영속 갱신 신호는 내용 revision과 무관하게 처리한다. 실제 프로토콜은 관련 API 문서를 따른다.
- 역할 변경은 PERMISSIONS, 원본 날짜 변경은 DATE_CHIPS로 재조회를 알린다.
  참여 변경은 기존 PARTICIPANTS 이벤트를 재사용한다. 권한은 다음 저장에도 재검사한다.

### 6.2. 편집권 스키마 이력

- `V7__bundle_edit_leases.sql`은 이미 적용된 Flyway 이력으로 보존하며 수정하지 않는다.
- 런타임 계약은 `member_id`, `session_id`, 서버 `connection_id`, `token`, 만료 판단에
  필요한 heartbeat 시각을 사용한다.
- 이번 변경의 V8 마이그레이션은 기존 V7 파일을 고치지 않고 별도 migration으로 추가해
  `bundle_edit_leases.screen_id`를 삭제한다.

## 7. 추천 번들

관련 기능: `GROUP-01`~`GROUP-05`.

### 7.1. 묶기·사진 선정

- 같은 번치 멤버에게 동일한 추천 목록을 제공한다.
- 날짜 미확인 사진과 작성 중·발행 번들 사용 사진을 제외한다.
- 조정한 촬영 날짜를 사용하고 시각이 없으면 업로드 시각으로 대신하지 않는다.
- 위치·사진 내용 AI 없이 촬영 날짜·시각·업로더·업로드 묶음으로 계산한다.
- 같은 날짜의 시각 있는 사진을 시간순으로 놓고 4시간 이상 공백 또는 앞뒤 구간 업로더가 겹치지 않으면 나눈다.
  양쪽 각각 3장 이상일 때만 나누며 큰 공백부터 적용한다.
- 전날 22시 이후와 다음 날 3시 이전 사진 간격이 2시간 이내면 해당 자정 구간을 잇는다.
  이틀치 전체를 합치지 않으며 묶음의 기준 날짜는 첫날이다.
- 날짜만 있는 사진은 같은 업로드 묶음의 시각 있는 사진이 가장 많이 속한 묶음에 우선 배치한다.
- 결정되지 않으면 해당 업로더가 그날 한 묶음에만 올렸을 때 그 묶음에 배치한다.
  그래도 결정되지 않으면 사진이 많은 묶음, 동률이면 시각이 이른 묶음에 배치한다.
- 시각 있는 사진이 전혀 없으면 그 날짜를 한 묶음으로 본다.
- 공동 업로드 사진은 한 장으로 세고 업로더는 모두 센다.
- 연사는 짧은 촬영 간격과 경량 이미지 유사도로 묶어 대표 한 장을 남긴다.
- 연사 정리 후 6장 이상·업로더 2명 이상인 묶음만 추천한다.
- 사진을 적게 올린 멤버부터 최소 한 장씩 선정하고 시간대가 편중되지 않게 6~10장을 담는다.
- 공동 업로드 사진은 한 번만 선정하며 업로더 한 명의 선정 몫으로 센다.
- 날짜·촬영 시각 순으로 정렬하고 시각 없는 사진은 같은 날짜 뒤에 업로드 순으로 둔다.
- 첫 사진이 대표 사진이다. 카드·상세·적용에서 같은 사진·순서를 사용한다.
- 카드 미선정 사진도 사진함에 유지한다.

### 7.2. 제목·적용·수명

- 제목은 서버의 상황별 문장 목록에서 15자 이내로 생성한다.
- 특별한 날 → 첫 사진 묶음 → 3명 이상 번치 전원 업로드 → 이전 묶음 후 30일 이상 →
  자정 연결 → 요일·시간대 순으로 상황을 판단한다.
- 같은 목록의 제목과 최근 사용 문장을 제외한다. 남은 문장이 없으면 최근 사용 제외를 풀고 기본 문장으로 보완한다.
- 생성한 제목은 사진 추가·재조회로 바꾸지 않는다. 분리·병합으로 새 후보를 만들면 새 제목을 부여한다.
- 후보는 하나만 선택하며 다시 누르면 해제한다.
- 적용은 앱 선택을 교체할 뿐 초안을 생성하지 않는다. 기존 선택이 있으면 교체 확인 후 적용한다.
- 적용 후 추가·해제할 수 있으며 합계 20장을 넘길 수 없다. 여러 번 적용하면 마지막 후보를 생성 출처로 남긴다.
- 적용 사이 삭제된 사진은 제외한다. 추천으로 초안을 생성하면 그 후보를 다시 추천하지 않는다.
- 사진 추가·삭제·날짜 변경 시 묶음과 선정 사진을 재계산한다.
- 기존 사진이 일부 남고 분리·병합되지 않으면 같은 후보·제목을 유지한다.
- 분리·병합 시 기존 후보를 종료하고 조건을 충족한 새 묶음마다 후보를 생성한다.
- 사진 6장 미만·업로더 2명 미만이면 제외한다.
- 새 사진 추가 시에만 마지막 추가 시각을 갱신한다. 삭제로 노출 기간을 늘리지 않는다.
- 마지막 추가 시점부터 30일 후 만료한다. 하루 한 번 처리하며 최대 하루 지연을 허용한다.
- 분리·병합 후보도 묶음 내 가장 최근 사진 추가 시점을 기준으로 만료한다.
- 후보가 사라져도 사진함 사진은 유지한다.
- 열린 추천 시트·상세는 다음 진입 시 갱신하고 이미 적용한 선택은 후보 변경으로 바꾸지 않는다.

## 8. 발행

관련 기능: `BUNDLE-01`, `BUNDLE-04`.

발행 시 아래 조건을 모두 다시 검증한다.

| 조건 | 기준 |
| --- | --- |
| 요청자 | 현재 번치 멤버이며 생성자 또는 참여 중인 관리자 |
| 사진 | 사용 가능한 같은 번치 사진 1~20장 |
| 제목 | 공백 제거 후 1~40자 |
| 공개 범위 | 멤버 공개·공개 중 선택 완료 |
| 참여자 | 현재 번치 멤버 2명 이상 |
| 코멘트 | 모든 참여자가 유효한 1~400자 작성 |
| 저장 | 최종 요청 처리 시 최신 서버 저장 내용·권한·필수 조건 재검증 |
| 이미지 | 사진함 원본 삭제 후에도 유지되는 이미지 보존 완료 |

- 위치·날짜·캡션은 필수 조건이 아니다.
- 편집 화면의 첫 업로드 준비 판단에는 공개 범위 미선택을 차단 사유로 포함하지 않는다.
- 별도 공개 범위 화면의 최종 업로드가 선택한 범위와 최신 저장 내용을 원자적으로 발행한다.
  범위를 고르다 뒤로 가는 것은 저장하지 않는다. 다른 멤버가 입력 중이어도 허용한다.
- 오래된 revision만으로 발행을 거부하지 않는다. 최신 필수조건·권한 실패는 거부한다.
- 실제 발행자를 publishedBy로 저장하여 PUBLISHED 이벤트와 재조회에 제공한다.
  기존 발행본의 알 수 없는 발행자는 null이며 생성자로 추정하지 않는다.
- 발행 시 참여자를 기여자로 기록하고 발행 시각을 저장한다.
- 발행 사진은 이미지 자산을 직접 참조한다. 파일 복사 없이 이미지 참조·참여자 고정·상태 변경을 한 트랜잭션으로 확정한다.
- 발행 후 도착한 초안 편집은 거부한다.
- 재시도와 다른 키의 동시 발행 모두 한 번만 반영한다.
- 이미지 보존 실패는 발행 성공으로 처리하지 않는다. 처리 중 장애도 같은 요청으로 복구할 수 있어야 한다.
- 발행본은 번치 홈 「우리의 번들」에 포함하고 번치 멤버에게 알림을 보낸다.

## 9. 조회·수정·삭제·Stage

관련 기능: `DRAFT-11`, `DRAFT-13`, `BUNDLE-02`~`BUNDLE-07`, `PROFILE-01`, `PROFILE-02`.

- 홈에서 작성 중인 초안에 다시 진입할 수 있다. 초안 목록과 발행 목록을 구분한다.
  초안은 `updatedAt DESC,id DESC`, 발행본은 `publishedAt DESC,id DESC`로 정렬한다.
  편집권 획득·heartbeat·presence·조회는 내용 편집 시각과 정렬을 바꾸지 않는다.
- 외부 공개 조회에 초안을 포함하지 않는다.
- 상세는 제목·순서 있는 사진·캡션·참여 멤버·코멘트·공개 범위·선택 위치·날짜를 제공한다.
- 발행본 공용 내용은 현재 메인 관리자 OWNER만 전체 일괄 저장한다. 사진 1~20장과 제목·공개 범위를
  검증하며 발행 후 나간 참여자를 발행 조건으로 다시 막지 않는다. 발행 시각·반응·댓글을 유지한다.
- 발행본 수정은 현재 번치 소속·수정 권한·내용 버전을 검사한다. 초안용 편집권은 요구하지 않는다.
- 기존 발행 사진은 원본 Photo가 삭제돼도 유지하고 수정할 수 있다. 새로 추가하는 사진은 현재 사진함의 유효성을 검사한다.
- 발행 후 참여자·멤버별 코멘트는 누구도 수정하지 않는다. 나간/탈퇴 멤버의 원문은 보존하고
  「작성자」·「삭제된 코멘트입니다」로 표시하며 같은 계정 재참여 시 복구한다.
- 초안 폐기·번들 삭제 시 사진함 원본을 유지하며 삭제 알림은 보내지 않는다.
- Stage는 PUBLIC/PRIVATE 전체 발행 번들 수로 계산하며 별도 저장하지 않는다. 내부·외부 모두 같은 기준을 쓴다.

| 현재 발행 번들 수 | Stage |
| --- | --- |
| 0~1 | 1 |
| 2~5 | 2 |
| 6~9 | 3 |
| 10 이상 | 4 |

- 임계값은 `bunch.bundle.stage-thresholds` 설정으로 관리한다. 기본값은 `0,2,6,10`이며
  `BUNCH_BUNDLE_STAGE_THRESHOLDS`로 지정할 수 있다. 0으로 시작하는 오름차순 4개 값을 사용한다.
- 삭제로 발행 수가 줄면 Stage도 내려간다. 상승 시 멤버 전원에게 알리고 하락 시에는 알리지 않는다.

## 10. 알림

관련 기능: `NOTI-02`, `NOTI-04`.

- 초안 생성·참여 추가·타인에 의한 제외·발행·Stage 상승 시 대상자에게 알린다.
- 코멘트 미작성자에게 참여 시점 기준 24시간·72시간에 각 1회, 최대 2회 독촉한다.
- 최초 참여자는 초안 생성, 이후 추가한 참여자는 추가 시점부터 계산한다.
- 작성 완료·참여 제외·발행·초안 삭제 시 남은 독촉을 취소한다.
- 독촉의 앱 내 알림은 생성하고 푸시는 수신 설정을 따른다.
- 변경 재시도로 알림을 중복 생성하지 않는다.

## 11. 사진함 연동

번들은 Photo ID로 참조하며 업로드·중복 판별·파일 처리는 사진함이 담당한다.
같은 사진의 공동 업로더는 Photo와 회원의 별도 연결로 관리한다.
앱이 정리해 전달한 촬영 날짜·선택적 촬영 시각을 저장하고 서버에서 시차를 재변환하거나 업로드 시각으로 보충하지 않는다.

| 사진함 제공 정보·동작 | 번들 처리 |
| --- | --- |
| Photo ID·번치 ID·처리 상태·업로더 전체 | 사진 유효성·소속 검증, 최초 참여자 계산 |
| 촬영 날짜·시각 유무·업로드 묶음 | 날짜 추천·번들 추천 계산 |
| 업로드 성공·중복 병합 Photo ID와 선택 순서 | 성공 사진 연결·중복 방지 |
| 공동 업로더 제거 | 다른 업로더가 남으면 사진 유지 |
| 최종 Photo 삭제 | 초안 사진·캡션 제거, 추천 재계산 |
| 촬영 날짜 변경 | 추천 칩·후보 갱신, 지정한 번들 날짜 유지 |
| 발행 이미지 보존·해제 | 사진함과 독립적으로 발행 이미지 참조 유지 |

- 클라이언트의 이미지 URL·업로더·번치 정보를 신뢰하지 않고 서버 Photo 정보를 검증한다.
- 사진 검증부터 연결·발행까지 삭제 경합을 보호한다.
- 삭제가 먼저 확정되면 새 연결·발행을 막고, 발행이 먼저 확정되면 이후 원본 삭제에도 발행 사진·순서·캡션을 유지한다.
- Photo 삭제와 파일 삭제를 분리하고 발행본에서 사용하는 파일은 보존한다.
- 같은 Photo 삭제가 반복돼도 사진·캡션·초안 정리 결과를 중복 적용하지 않는다.
- 외부 삭제로 초안 사진이 0장이 되면 초안을 영구 삭제한다.
- 번치 나가기·내보내짐·탈퇴 시 업로더 연결을 제거하고 마지막 업로더가 없으면 Photo와 초안 사진을 제거한다.
- 발행 사진·캡션·기여 기록은 번치 이탈로 삭제하지 않는다.
- 회원 탈퇴 시 작성자는 「탈퇴한 멤버」, 코멘트는 탈퇴 안내 문구로 대체한다.
- 번치 나가기·내보내기의 소속 변경과 Photo·초안·코멘트·편집권 DB 정리는 같은 트랜잭션으로 처리한다.
  하나라도 실패하면 소속 변경을 포함한 DB 변경 전체를 롤백한다.
- 초안·발행본 삭제 시 사진함이나 다른 발행본이 사용하는 공유 파일을 삭제하지 않는다.
- 프로필·사진함·발행본의 모든 참조가 사라진 파일만 DB 커밋 후 삭제를 시도한다.
  외부 파일 삭제 실패는 파일 식별자를 로그에 남기며 이미 완료한 DB 변경을 되돌리지 않는다.

## 12. 실패 처리·수용 기준

- 모든 변경에서 계정·소속·권한·대상 상태를 다시 검증한다.
- 생성·발행은 요청 키로 중복을 막는다. 같은 키·다른 입력은 충돌로 거부한다.
- 재시도도 현재 접근권한을 검사하며 삭제한 번들을 복원하지 않는다.
- 응답 유실·동시 편집으로 중복 변경·무음 덮어쓰기가 발생하지 않아야 한다.
- 저장 실패 시 기존 서버 데이터와 앱의 미저장 입력을 유지한다.
- 복구 정보는 접근 가능한 번치·번들 데이터로 제한한다.

| 범위 | 검증 기준 |
| --- | --- |
| 생성 | 멤버 2명·초안 10개·사진 1~20장, 삭제/다른 번치 사진 거부, 단일 생성 |
| 참여 | 최초 업로더 합집합·참여자 추가/제외 권한·생성자 이탈 시 초안 삭제 |
| 텍스트 | 40/400/200자·이모지·공백·줄바꿈, 타인 코멘트 편집 거부 |
| 사진 | 중복·마지막 1장 보호·동시 이동/제거·차이 병합·캡션 귀속 |
| 공동 편집 | CRDT 수렴·41자 초과·사진/장소 의도·날짜 마지막 저장·다중 연결·BEGIN/END editing 15초·TYPE 3초·입장 presence 15초·미전송 입력 폐기. legacy 캡션 lease는 별도 회귀 |
| 추천 | 미확인/사용 사진 제외·시각/업로더 묶기·6~10장·분리/병합·30일 만료 |
| 발행 | 최종 범위+최신 내용 원자 처리·실제 발행자·권한 재검증·단일 발행·뒤늦은 수정 거부 |
| 원본 독립성 | 삭제/발행 경합·최종 업로더 제거 후 발행 사진/캡션/순서 유지 |
| 삭제·조회 | 초안 전체 정리·사진함 원본/공유 파일 유지·외부 초안 비노출 |
| 이탈 정리 실패 | 소속·후임·초대·Photo·초안 DB 변경 전체 롤백, 외부 파일 삭제 실패는 별도 기록 |
| Stage | 0/1/2/5/6/9/10개 경계·공개/비공개 합산·설정 기준·삭제 후 하락 |

영속성·한도·멱등성·동시 요청은 실제 DB에서 검증한다.
사진함 연동은 실제 Photo와 이미지 저장소에서 검증한다.
iOS/WebView의 사진 선택·권한·입력·연결 복귀·화면 갱신은 서버 테스트와 별도로 검증한다.
