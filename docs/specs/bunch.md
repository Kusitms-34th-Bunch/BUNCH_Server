# 번치 Spec

## 기준·범위·상태

기준 원문은 [BUNCH 상세 기능명세서 — 번치 5장](https://docs.google.com/spreadsheets/d/1ScziF7WoYLHRiC_UYJBkKsi0jL6KKQJD2TNDzW1QGfU/edit?gid=2104162394#gid=2104162394)의 47개 항목이다.
번치 소유 44개 항목(5.1~5.11)은 아래에, 알림 소유 3개 항목(5.12)은 [알림 Spec](notification.md)에 보존한다. 전체 번호·기능 ID는 아래 47개 추적표로 연결한다. 최초 작성은 2026-10-29이며 2026-10-31 최신 시트를 다시 대조했다.
외부 뭉치 단계는 같은 날 사용자 답변에 따라 내부와 같은 실제 전체 발행 수 기준으로 확정한다.
같은 날 최종 사용자 답변에 따라 직접 나가기(LEFT)·내보내짐(REMOVED) 모두 유효한 초대로 재참여할 수 있다.
남아 있는 발행본의 작성자 이름·프로필·코멘트 연결은 복구하되 삭제된 사진함·초안과 이전 관리자 권한은 복구하지 않는다.
화면의 정확한 배치·기호·문구는 원문 추적표의 셀 링크를 함께 따른다. 아래 본문은 서버 책임과 실패 동작을 연결하며,
명시한 승인 보완 외에 원문의 상세 동작을 생략·대체하는 근거로 사용하지 않는다.

**이 문서는 후속 구현을 위한 제품 계약이며 구현 완료 보고가 아니다.**
문서 작업의 기반은 `dev`의 `159937b6`이다. PR #32는 번들 생애주기·조회·통계·이탈 정리의 선행 작업이며,
이 문서의 새 역할·권한·단계 기준이 그 PR이나 기반 코드에 이미 반영되었다고 가정하지 않는다.
기능 구현은 #32 병합 후 최신 `dev`에서 시작한다. 나가기·내보내기는 #25, 사진 이탈 정리는 #38과 연결한다.
필요한 4개 작업만 요청 키를 쓰며 알림·푸시의 최소 저장/전송 구조는 [알림 스키마](notification-schema.md)가 소유한다.
47개 제품 요구·21종 알림·권한·이탈 원자성은 유지한다.

- **확정 요구사항:** 최신 5장 원문과 이번 승인 계획에서 확정한 정책이다. 충돌하는 과거 PRD·번들 Spec의 해당 정책보다 우선한다.
- **승인된 보완:** 참여자별 리마인드 시점, 원본 선택과 서버 이미지 전송의 구분 등 이번 계획에서 명시한 결정이다.
- **원문 제안·디자인 미정:** 그대로 상태를 보존한다. 확정 기능이나 구현 완료로 승격하지 않는다.
- 이 범위 밖의 정책은 [PRD](../PRD.md), [인증 Spec](auth.md), [온보딩 Spec](onboarding.md),
  [로그인·온보딩 API 계약](login-onboarding-api.md), [번들 Spec](bundle.md), [사진함 기반 계약](photo-foundation.md)을 따른다.
- HTTP 경로·DTO·오류 코드·버전·요청 키의 구체 계약은 [번치 API 계약](bunch-api.md),
  번치 테이블·제약·마이그레이션·잠금은 [번치 DB 계약](bunch-schema.md)에서 정한다.
  알림·기기·개인 설정·푸시 전송 계약은 [알림 Spec](notification.md)·[알림 API](notification-api.md)·[알림 스키마](notification-schema.md)가 소유한다.
  본문과 연결 문서는 목표 계약이며 서버 API가 이미 제공된다는 뜻은 아니다.

### 기존 정책과의 충돌 정렬

| 항목 | 이 문서에서 적용할 확정 정책 |
| --- | --- |
| 관리자 구조 | 동일 권한의 복수 Owner 대신 메인 관리자 1명과 공동 관리자 여러 명. `OWNER / CO_OWNER / MEMBER`로 구분 |
| 발행본 공용 내용 수정·삭제 | 생성자·공동 관리자 권한을 제거하고 현재 메인 관리자만 허용. 본인 코멘트 작성자 권한은 유지 |
| 초안 삭제 | 생성자 또는 해당 초안에 참여 중인 관리자만 가능. 미참여 관리자에게 전역 삭제 권한 없음 |
| 초안 생성자 이탈 | 생성자 권한 승계 없이 해당 초안 삭제. 발행본은 보존 |
| 번치 재참여 | LEFT·REMOVED 모두 허용. 새 Membership의 MEMBER로 참여하고 남아 있는 발행 기록의 본인 표시만 복구. 삭제 데이터·관리자 권한은 복구하지 않음 |
| 뭉치 단계 | 과거 5단계·4개 간격 대신 4단계, 시작 기준 `0 / 2 / 6 / 10` |
| 메인 관리자 번치 나가기 | 공동 관리자 유무와 관계없이 후임 직접 선택 필수. 계정 탈퇴의 자동 승계와 구분 |
| 다른 소속 번치에 대한 행동 | 현재 번치와 다르면 외부 프로필로 보며 현재 번치 명의 팔로우·차단·신고 허용 |
| 코멘트 리마인드 | 원문 생성 후 24·72시간을 참여자별 참여 후 24·72시간으로 보완. 나중 참여자도 같은 간격 보장 |
| 프로필 저장 | 관리 화면은 이미지·이름·소개·공개 범위 일괄 저장. 생성 완료 화면의 사진 즉시 저장과 구분 |

### 공통 책임과 불변 조건

| 주체 | 책임 |
| --- | --- |
| 앱 내부 WebView | 화면 구성·모달·입력 검증·미리보기·새로고침·목록 상태·버튼 연타 방지·오류 문구·현재 번치 전환 |
| iOS 네이티브 | 사진 접근·선택·편집, JPEG 변환·위치 EXIF 제거, OS 설정·공유 화면, 푸시 권한·기기 등록·딥링크와 인증 후 복귀 |
| 서버 | 가입 완료·활성 소속·역할·대상 상태 재검증, 개수·노출·정렬·유일성, 원자적 변경·중복 방지, 이탈·삭제 정리, 알림 기록·전송 대기 |

현재 번치는 행동의 명의이며 로그인한 회원은 실제 실행자다. 서버는 각 요청에서 현재 번치의 활성 Membership을
검증한다. 클라이언트가 전달한 역할·개수·팔로우 상태나 숨긴 버튼을 신뢰하지 않는다.
가입 중 계정은 번치 기능을 이용할 수 없다. 가입 완료 후 소속이 0개인 회원의 공개 피드 탐색은 기존 계약을 유지하되,
번치 명의 행동에는 유효한 현재 번치가 필요하다. 개인 계정 `member`와 번치 소속 Membership은 다른 개념이다.

변경 요청은 현재 역할·소속·대상 버전을 재확인한다. 멤버 관리 대상은 회원 ID만으로 재탐색하지 않고
**해당 참여 회차의 Membership ID**로 식별한다. 재참여는 새 소속이며 종료된 소속을 ACTIVE로 되돌리지 않는다.
과거 내보내기·역할 변경·나가기 요청은 새 Membership에 적용하지 않는다. 과거 참여 성공 요청만으로 재참여시키지 않는다.
신규 요청 키는 프로필 저장·인계·나가기·번치 삭제에만 사용한다. 다른 변경은 상태·대상 ID·유일성·버전으로 중복을 막는다.
같은 요청 재생이 변경이나 알림을 반복하지 않으며,
응답 유실과 확정 실패를 구분해 최신 결과를 확인한다. 외부 파일·푸시 실패 때문에 완료된 업무를 되돌리지 않는다.

역할·인계·이탈·삭제는 번치 단위로 직렬화한다. 메인 관리자는 활성 번치에 정확히 1명이며,
서버 트랜잭션과 DB 유일성 제약으로 중복 메인 관리자를 방지한다. 마지막 메인 관리자만 먼저 제거한 상태를 커밋할 수 없다.
사진·초안·편집권 정리와 소속 종료는 하나의 업무 트랜잭션이고, 파일 정리는 참조 확인 후 커밋 뒤 처리한다.
기존 기능의 잠금 순서를 지키며 API·DB 계약에서 경합과 재시도 규칙을 함께 고정한다.

모든 API는 `/api/v1`, `success / data / error`, 서버 UTC 시각 계약을 유지한다.
이 문서의 상대 시간·모달·문구와 이미지 디자인은 앱 표시 책임이며 서버는 안정적인 상태·시각·판정 결과를 제공한다.
본문의 성공 토스트는 원문대로 화면 하단에 표시한다.

### 역할·참여 권한의 기준표

`OWNER`는 메인 관리자, `CO_OWNER`는 공동 관리자, `MEMBER`는 일반 멤버다.
관리자라는 표현은 두 관리자 역할을 함께 뜻하며 **메인 관리자 전용 행동은 아래에서 별도로 제한**한다.
초안 생성자·참여자 여부는 번치 역할과 독립적이다.

| 행동 | OWNER | CO_OWNER | MEMBER |
| --- | --- | --- | --- |
| 내부 홈·사진함·초안 목록·멤버·차단 목록 보기, 멤버 초대 | 허용 | 허용 | 허용 |
| 번치 프로필 편집·공개 범위 변경·번치 삭제 | 허용 | 불가 | 불가 |
| 공동 관리자 지정·해제, 메인 관리자 권한 인계 | 허용 | 불가 | 불가 |
| 멤버 내보내기 | 다른 공동 관리자·일반 멤버 | 일반 멤버만 | 불가 |
| 다른 멤버의 사진 삭제·날짜 변경 | 허용 | 허용 | 불가(본인 업로더 권한은 별도) |
| 다른 번치 차단·해제 | 허용 | 허용 | 불가 |
| 번치 명의 팔로우·취소·요청 승인·거절·신고 | 허용 | 허용 | 허용 |
| 초안 공용 내용 편집·참여 멤버 추가 | 참여자일 때 | 참여자일 때 | 참여자일 때 |
| 초안 발행·다른 참여 멤버 제외·초안 삭제 | 생성자 또는 참여 중인 관리자 | 생성자 또는 참여 중인 관리자 | 생성자일 때만 |
| 발행된 번들 공용 내용 수정·번들 삭제 | 허용 | 불가 | 불가 |
| 본인 코멘트 작성·수정 | 작성자 규칙 | 작성자 규칙 | 작성자 규칙 |
| 다른 사람 코멘트 수정·삭제·숨김 | 불가 | 불가 | 불가 |
| 번치 나가기 | 후임 직접 지정 후 | 바로 나가기 | 바로 나가기 |

본인 카드 관리·자기 내보내기·메인 관리자 내보내기는 허용하지 않는다.
초안 최초 생성자는 타인이 참여자에서 제외할 수 없고 스스로 빠지면 초안을 삭제한다.
발행본 공용 내용은 제목·사진 구성·순서·캡션·공개 범위 등을 뜻한다. 메인 관리자도 발행 조건을 깨는 수정은 할 수 없다.
본인 발행 코멘트는 작성자가 수정하되 비우거나 삭제할 수 없다. 번치 이탈 뒤 작성 권한이 유지된다는 뜻은 아니다.

## 5.1 번치 메인 탭

<a id="bunch-5-1-1"></a>
### 5.1.1 번치 메인 화면 구성

기능 ID: `BUNCH-02`, `BUNCH-03`.

- **앱:** 하단 탭은 「피드 / 사진함 / 번치 / 마이페이지」 순서이며 번치가 선택된다.
  헤더 → 뭉치 → 프로필(가볼 곳 버튼 포함) → 번들 탭 영역 순으로 구성한다.
  헤더·하단 내비게이션·오른쪽 아래 「+」는 고정하고 본문만 스크롤한다.
  탭 자체에는 뒤로가기가 없으며 더보기·알림은 그 위에 열린다. 작성 중인 번들은 별도 화면이 아닌 메인 안의 탭이다.
- **서버:** 현재 번치의 이름·이미지·소개·공개 범위·뭉치 유형, 팔로워·팔로잉·멤버 수, 발행 목록·개수와 초안 수를 제공한다.
  단계는 발행 수에서 계산한다. 번치 탭 진입·앱 복귀·당겨 새로고침 때 갱신하며 홈 전체의 실시간 동기화는 요구하지 않는다.
  전환하면 모든 데이터를 새 번치 기준으로 다시 조회한다.
- **예외:** 활성 소속 0개면 번치 없음 화면. 삭제·내보내짐이면 접근 불가 안내.
  로딩 실패는 「일시적인 오류가 발생했어요. 다시 시도해 주세요」를 표시한다.

<a id="bunch-5-1-2"></a>
### 5.1.2 헤더(번치 전환·알림·더보기)

기능 ID: `BUNCH-04`, `NOTI-01`, `BUNCH-07`.

- **앱:** 왼쪽 원형 이미지·이름·아래 화살표는 전환 시트를 연다. 오른쪽 종은 현재 번치 알림 목록,
  더보기는 역할별 메뉴를 연다. 헤더는 고정하며 긴 이름은 한 줄 말줄임한다.
- **서버:** 현재 회원·현재 번치의 안 읽은 알림 수를 제공하고 진입·앱 복귀 때 갱신한다.
  1개 이상이면 빨간 점을 표시한다. 다른 번치 알림은 전환 목록 배지로 구분한다.
- **예외:** 설정 사진이 없거나 로딩에 실패하면 생성 때 선택한 뭉치 기본 이미지를 사용한다.

<a id="bunch-5-1-3"></a>
### 5.1.3 뭉치 영역

기능 ID: `PROFILE-01`, `PROFILE-02`.

뭉치와 관련 오브젝트를 크게 표시하며 탭 동작은 없다. 생성 때 확정한 뭉치 유형과 현재 단계의 조합으로 이미지를 고른다.
유형은 생성 후 변경하지 않으며 프로필 사진 교체로 바뀌지 않는다.

| 현재 발행된 번들 수 | 단계 |
| --- | --- |
| 0~1 | 1 |
| 2~5 | 2 |
| 6~9 | 3 |
| 10 이상 | 4 |

서버는 기준값 `0 / 2 / 6 / 10`을 설정으로 관리하고 단계 자체를 저장하지 않는다.
외부 프로필에서도 공개·비공개 발행본을 모두 포함한 같은 실제 단계를 표시한다. 외부용 단계를 따로 계산하지 않는다.
초안·좋아요·팔로워 수는 계산에 넣지 않는다. 발행본 삭제 시 하락하며 사용자 수동 변경은 없다.
상승 시 성장 알림을 보내고 하락 시 보내지 않는다. 10개 이후는 4단계를 유지하고 추가 단계는 서비스 업데이트 때 정한다.
이미지·오브젝트의 최종 디자인과 변화 순간 연출은 **디자인 확정 대기**다. 리소스 실패는 회색 자리표시로 대체한다.

<a id="bunch-5-1-4"></a>
### 5.1.4 번치 프로필 영역

기능 ID: `BUNCH-02`, `FEED-03`.

이름 오른쪽에 비공개일 때만 자물쇠를 표시하고 소개는 내부 줄바꿈·전체 내용을 살려 보여준다.
「N 팔로워 / N 팔로잉 / N 멤버」를 표시한다. 팔로워·팔로잉 탭은 해당 목록의 선택 탭으로,
자기 번치의 멤버 수는 내부 멤버 관리로 이동한다. 원문의 외부 멤버 목록 참조는 자기 번치에서는 적용하지 않는다.
같은 줄 오른쪽에는 깃발 아이콘과 「가볼 곳」 버튼을 두고 우리 번치의 가볼 곳 화면으로 이동한다.
다른 번치의 번들 위치를 우리 번치 명의로 저장·모아 보는 상세 동작은 별도 가볼 곳 명세에서 정한다.
이 문서는 그 기능의 저장 테이블·쓰기 API를 추측해 추가하지 않는다.

서버는 승인 대기 요청을 팔로워 수에 넣지 않고 차단 관계를 팔로워·팔로잉 수에서 제외한다.
멤버 수는 활성 소속만 센다. 소개가 길어도 최대 50자 범위에서 줄을 늘려 모두 표시한다.

### 5.1.5 번들 탭 영역

  대표 사진은 첫 사진이다. 카드 탭은 번들 상세로 이동한다.
- 발행본이 0개면 초안 유무와 관계없이 번들 탭에 「추억은 많은데, 번들은 아직!」 /
  「함께한 순간을 하나의 기록으로 남겨보세요.」와 「첫 번들 만들기」를 표시한다.
  작성 중인 번들 탭의 목록·빈 상태는 5.3.1을 따른다.

  스크롤로 추가 조회한다. 추가 조회 실패는 기존 목록을 유지하고 다음 하단 스크롤에서 재시도한다.
- 이미지 실패는 회색 자리표시. 삭제된 카드 선택은 「삭제된 번들이에요」 후 목록 갱신이다.

<a id="bunch-5-1-6"></a>
### 5.1.6 번들 만들기 버튼(+)

기능 ID: `DRAFT-01`.

현재 번치 멤버 모두에게 하단 내비게이션 위의 고정 「+」를 보여주며 번들 만들기로 이동한다.
서버는 생성 시 소속·한도를 재검증한다. 번치 멤버가 1명이면 멤버 초대를 안내하고 생성하지 않는다.
번치당 초안 10개가 차 있으면 기존 번들 생성 한도 예외를 따른다. 버튼 표시가 생성 허용을 보장하지 않는다.

<a id="bunch-5-1-7"></a>
### 5.1.7 번치가 없을 때 번치 탭

기능 ID: `BUNCH-06`.

소속 0개로 진입하거나 마지막 번치를 나가거나 삭제하면 「참여 중인 번치가 없어요」 /
「새 번치를 만들거나 초대받은 번치에 참여해보세요.」를 표시한다.
「새 번치 만들기」는 생성 1단계, 「초대 링크 참여하기」는 링크 입력으로 연결한다.
전환·알림·더보기·번들 「+」는 숨기고 하단 탭은 유지한다. 생성·참여 성공 후 해당 홈을 연다.
중단은 각 온보딩 흐름의 규칙을 따른다.

## 5.2 번치 전환

화면 가운데 안내를 두고 두 진입 버튼은 세로로 배치한다.

<a id="bunch-5-2-1"></a>
### 5.2.1 번치 전환 시트

기능 ID: `BUNCH-04`.

어두운 배경 위 손잡이·「번치 전환하기」·X가 있는 시트를 연다.
원형 이미지·이름의 목록에서 현재 번치는 맨 위 비활성, 나머지는 최근 사용순이다.
읽지 않은 알림은 「알림 N개」, 삭제·내보내진 기록은 흐린 행과 「접근 불가」로 표시한다.
접근 불가 행은 전환할 수 없지만 눌러 안내 모달을 열 수 있다. 아래 「+ 새로운 번치 추가하기」를 둔다.
X·아래로 끌기·바깥 탭으로 닫는다.

서버는 회원별 활성 소속과 접근 불가 안내를 구분해 제공한다. 활성 소속 한도는 10개이며 안내 기록은 세지 않는다.
최근 사용 동률은 기존 소속 계약의 소속 ID 내림차순으로 결정한다. 긴 이름은 말줄임한다.
조회 실패는 공통 일시 오류 토스트 후 시트를 닫는다.

<a id="bunch-5-2-2"></a>
### 5.2.2 다른 번치로 전환

기능 ID: `BUNCH-04`, `BUNCH-05`.

다른 활성 행을 탭하면 확인창 없이 시트를 닫고 새 번치 홈을 조회한다.
성공 시 「{번치 이름} 번치로 전환했어요.」를 표시하고 서버의 마지막 사용 번치·사용 시각을 갱신한다.
사진함·번들 생성·초안·알림·팔로잉 피드와 팔로우·좋아요·댓글·신고·차단의 명의를 모두 새 번치로 바꾼다.
진행 중인 사진 업로드의 대상은 시작 당시 번치로 고정한다.

현재 행은 무동작, 접근 불가 행은 안내만 연다. 연타는 첫 탭만 처리한다.
대상이 삭제·내보내짐 상태가 됐으면 전환하지 않고 접근 불가 안내를 연다.
네트워크 실패는 공통 토스트 후 기존 번치를 유지한다. 다른 번치 응답이 늦게 와도 새 화면에 섞지 않는다.

<a id="bunch-5-2-3"></a>
### 5.2.3 삭제된·내보내진 번치 안내

기능 ID: `BUNCH-04`.

| 사유 | 제목 | 내용 | 버튼 |
| --- | --- | --- | --- |
| 번치 삭제 | 「{번치 이름} 번치가 삭제됐어요」 | 「관리자가 번치를 삭제하여 더 이상 접근할 수 없어요.」 | 「번치 목록에서 삭제」 |
| 내보내짐 | 「{번치 이름} 번치에서 내보내졌어요」 | 「번치 멤버 목록에서 제외되어 더 이상 번치에 참여할 수 없어요.」 | 「번치 목록에서 삭제」 |

원문 안내의 「더 이상 번치에 참여할 수 없어요」는 현재 소속의 접근 종료를 뜻하며 영구 재참여 금지가 아니다.
내보내진 회원도 새 유효 초대로 일반 멤버로 재참여할 수 있다. 14번 푸시 문구도 같은 의미로 적용한다.

접근 불가 행 선택은 전환하지 않고 위 모달을 연다. 확인 버튼 성공 후 행만 제거하며 다른 정상 화면은 유지한다.
바깥 탭은 모달만 닫고 행을 남긴다. 현재 보고 있던 번치의 접근 상실이면 다음 정보 조회 때 같은 안내를 열고,
확인 후 가장 최근 사용한 남은 번치 홈 또는 소속 0개 화면으로 이동한다.
앱 최초 실행·로그인 도착은 기존 계약처럼 무효한 마지막 번치를 건너뛰어 유효한 번치로 복귀한다.
이미 열린 화면의 다음 조회에서 안내하는 것과 구분한다.

서버는 번치 삭제에 함께 사라지지 않는 회원별 안내 기록(tombstone)에 사유·발생 당시 번치 이름·시각·참여 회차를 보존한다.
본인 나가기·본인 직접 삭제에는 만들지 않는다. 확인 삭제 또는 발생 후 30일 경과로 제거하며 활성 소속 수·알림 수에 넣지 않는다.
새 참여 회차와 과거 안내를 혼동하지 않는다. 확인 실패는 공통 토스트 후 행을 유지한다.
내보내짐은 이 안내와 푸시로만 알리고 앱 내 알림 목록에는 쌓지 않는다.

<a id="bunch-5-2-4"></a>
### 5.2.4 새로운 번치 추가하기

기능 ID: `BUNCH-06`.

「+ 새로운 번치 추가하기」는 시트를 닫고 기존 번치 시작 선택으로 이동한다.
새 번치 만들기 또는 초대받은 번치 참여를 선택하고 성공한 번치를 현재 번치로 삼는다.
활성 소속이 10개면 이동하지 않고 「참여할 수 있는 번치는 최대 10개예요.」를 표시한다.
서버도 생성·참여 최종 시점의 한도를 검증한다.

## 5.3 작성 중인 번들

<a id="bunch-5-3-1"></a>
### 5.3.1 작성 중인 번들 탭

기능 ID: `DRAFT-11`.

- 메인의 연필 아이콘 탭을 선택하면 별도 화면 이동 없이 세로 카드를 표시한다.
  왼쪽 대표 첫 사진, 오른쪽 제목(빈 값이면 흐린 「제목 미정」), 제목 아래 겹친 참여 멤버 프로필 이미지를 보여준다.
  카드 오른쪽 위 휴지통은 삭제 권한자에게만 표시한다. 0개면 이 탭 안에 「작성 중인 번들이 없어요」를 표시한다.
- 번치 멤버는 동일한 전체 초안 목록을 보며 미참여자는 조회만 한다. 카드 탭은 공동 편집 화면으로 이동하되
  참여 여부에 맞는 읽기 전용 상태를 적용한다. 삭제 버튼은 권한자에게만 보인다.
- 서버는 **마지막 편집 시각 최신순**으로 제공한다. 최대 10개이며 오래된 초안을 자동 삭제하지 않는다.
  생성·발행·삭제는 재진입·새로고침 때 반영하며 발행·삭제된 항목은 제외한다.
- 갱신 결과 0개면 탭을 유지하고 빈 상태를 표시한다. 선택한 초안이 삭제됐으면 「삭제된 번들이에요.」,
  발행됐으면 「발행된 번들이에요.」 후 목록 갱신. 조회 실패는 공통 일시 오류 토스트다.

<a id="bunch-5-3-2"></a>
### 5.3.2 작성 중인 번들 삭제

기능 ID: `DRAFT-13`.

휴지통은 생성자 또는 해당 초안에 참여 중인 메인·공동 관리자에게만 표시한다.
미참여 관리자에게 표시하지 않으며 서버가 현재 역할·참여 여부를 다시 확인한다.
확인 모달은 「작성 중인 번들을 삭제할까요?」 /
「삭제한 번들은 다시 복구할 수 없지만, 사용된 사진은 사진함에 그대로 남아요.」와 「취소 / 삭제하기」다.
취소·바깥 탭은 닫기만 한다. 성공 시 카드를 즉시 제거하고 「작성 중인 번들을 삭제했어요.」를 표시한다.

제목·캡션·코멘트·참여·위치·날짜·공개 범위·편집권을 함께 영구 삭제한다. 사진함 Photo는 유지하며
사진은 추천 계산 대상으로 돌아간다. 변환한 날짜·여행의 재제안 억제와 결합하는 상세 정책은 기존 미정 항목을 별도로 해소한다.
삭제 알림은 없다. 생성자가 스스로 참여에서 빠지거나 나가기·내보내짐·계정 탈퇴로 이탈하면 같은 방식으로 초안을 삭제한다.
사진함 정리로 초안 사진이 0장이 돼도 자동 삭제한다.

편집 중인 다른 참여자에게 삭제 상태를 반영해 「삭제된 번들이에요.」 후 이전 화면으로 돌리고 열린 편집권·연결을 종료한다.
발행과 삭제의 경합은 먼저 완료한 상태 변경만 성공한다. 이미 발행이면 「이미 발행된 번들이에요.」 후 목록 갱신,
이미 삭제면 「이미 삭제된 번들이에요.」 후 이전 화면으로 이동한다.
권한 상실은 「번들은 초안을 만든 멤버나 참여 중인 관리자만 삭제할 수 있어요.」 후 버튼을 숨긴다.
요청 실패는 공통 토스트 후 확인 시트를 유지한다.

## 5.4 더보기

<a id="bunch-5-4-1"></a>
### 5.4.1 더보기 메뉴(역할별 메뉴)

기능 ID: `BUNCH-07`.

뒤로가기는 홈으로 돌아간다. 메뉴 순서는 다음과 같다.

| 역할 | 위에서부터 표시할 메뉴 |
| --- | --- |
| 메인 관리자 | 프로필 편집 / 멤버 관리 / 멤버 초대 / 차단 목록 / 번치 나가기 / 번치 삭제 |
| 공동 관리자 | 멤버 관리 / 멤버 초대 / 차단 목록 / 번치 나가기 |
| 일반 멤버 | 멤버 관리 / 멤버 초대 / 차단 목록 / 번치 나가기 |

메뉴에서 여는 초대는 X 대신 뒤로가기를 쓰고 「나중에 할게요」를 숨긴다.
역할이 바뀌면 다음 메뉴 진입 때 갱신한다. 기능 진입·실행 시 서버 권한을 다시 확인하고,
권한이 사라졌으면 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 새 역할의 메뉴로 갱신한다.

## 5.5 번치 프로필 편집

헤더에는 왼쪽 뒤로가기만 표시하고 번치 메인으로 돌아간다.

<a id="bunch-5-5-1"></a>
### 5.5.1 번치 프로필 편집 화면 구성

기능 ID: `BUNCH-08`.

메인 관리자만 진입하며 서버도 저장 시 재확인한다. 제목 없는 뒤로가기 아래 원형 이미지·카메라 버튼,
이름·소개 입력과 글자 수, 공개 범위 카드, 하단 「저장하기」를 표시한다. 저장된 값으로 시작하고
모든 변경은 앱 임시 상태에서 관리해 저장 버튼에서 한꺼번에 반영한다.
뒤로가기 시 변경이 없으면 바로 복귀하고, 변경이 있으면 「저장하지 않고 나갈까요?」 /
「변경한 내용이 반영되지 않아요.」 / 「나가기 / 취소」를 표시한다. 나가기는 미저장 변경을 버린다.

진입 조회 실패는 공통 토스트 후 이전 화면으로 돌아간다. 편집 중 메인 관리자 권한을 잃으면 저장을 거부하고
「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 홈으로 돌아간다.

원형 이미지 오른쪽 아래에 카메라를 두고 이미지나 카메라를 누르면 사진 설정으로 진입한다.

<a id="bunch-5-5-2"></a>
### 5.5.2 번치 프로필 이미지 변경

기능 ID: `BUNCH-08`.

「프로필 사진 설정」 시트에 「앨범에서 사진 선택 / 기본 이미지 적용 / 취소」를 제공한다.
이미 기본 이미지면 초기화 항목은 숨긴다. 네이티브에서 사진 1장 선택 → 1:1·원형 가이드 확대·이동 편집 →
「완료」로 **미리보기만** 바꾸며, 취소하면 직전 상태를 유지한다. 기본 이미지 적용도 미저장 선택이다.
관리 화면의 「저장하기」 때 다른 값과 함께 반영하며 생성 완료 화면의 사진 즉시 저장 API와 구분한다.
뭉치 유형·홈의 뭉치 자체는 바뀌지 않는다.

| 단계 | 형식·용량·처리 |
| --- | --- |
| 기기에서 선택하는 원본 | 최신 시트의 JPEG·PNG·HEIC·WebP, **10MB 이하(10,000,000 bytes)**. 서버 JPEG 제한과 구분 |
| 앱 편집·전송 준비 | 1:1 자르기·크기 축소·JPEG 변환·위치 EXIF 제거 |
| 서버에 전송하는 프로필 파일 | 기존 계약의 **JPEG만, 최대 5MiB, 가로·세로 각각 최대 1024px, 정사각형** |
| 서버 저장 | 파일 검증·재인코딩 후 이미지 자산 연결. 기본 이미지는 `imageUrl:null`이며 유형 기본 이미지를 앱이 선택 |

원본이 10MB 이하여도 변환 파일이 서버 기준을 만족해야 한다. 사진함의 30MB·2560px 규칙을 프로필에 적용하지 않는다.
일괄 저장 실패 때 기존 프로필·사진 참조를 유지하며 새 임시 파일은 별도 정리한다.

사진 권한 거부는 「권한 설정이 필요해요」 /
「사진 접근 권한이 거부되어 있어요. 설정에서 직접 허용할 수 있어요.」 / 「취소 / 설정 열기」로 안내한다.
지원하지 않는 형식·손상 사진은 「이 사진은 사용할 수 없어요」 후 기존 미리보기를 유지한다.

사진 편집 화면의 제목은 「사진 편집」이다.

<a id="bunch-5-5-3"></a>
### 5.5.3 번치 이름·한 줄 소개 수정

기능 ID: `BUNCH-08`.

이름은 `n/12`, 소개는 `n/50`를 표시한다. 이름은 trim+NFC 후 1~12 코드 포인트,
한글·영문·숫자·ASCII 공백만 허용하며 대소문자·내부 공백을 구분하는 전체 번치 유일성을 유지한다.
특수문자·이모지·줄바꿈은 이름에서 허용하지 않는다. 생성 화면의 숫자 금지 오류 문구는 과거 오기이며 숫자는 허용한다.
소개는 앞뒤 공백·빈 줄 제거 후 1~50 grapheme로, 이모지·내부 줄바꿈을 허용하고 공백·줄바꿈만 있으면 빈 값이다.
앱은 초과 입력을 막고 붙여넣기 금지 문자·초과 길이를 생성 화면과 같이 처리한다. 서버는 잘못된 입력을 임의 교정하지 않고 거부한다.

이름 변경 입력 정지 0.5초 후 현재 번치를 제외해 중복 확인한다. 현재 이름과 같으면 조회하지 않는다.
「사용 가능한 번치 이름이에요」 / 「이미 사용 중인 번치 이름이에요」를 표시한다.
조회 실패는 결과 문구 없이 두고 저장 시 서버 최종 검증에 맡긴다. 이름·소개가 비거나 중복이면 저장을 비활성화한다.
늦게 온 중복 응답을 다른 입력의 결과로 표시하지 않는다. 서버는 저장 직전에 다시 유일성을 검사한다.
빈 곳·버튼 탭은 키보드를 닫고 입력란 간 이동은 키보드를 유지한다.

각 입력란의 글자 수는 입력란 오른쪽 아래에 표시한다.

<a id="bunch-5-5-4"></a>
### 5.5.4 번치 공개 범위 변경

기능 ID: `BUNCH-08`, `FEED-06`.

현재 선택으로 시작하는 단일 선택 카드 「공개 / 누구나 우리 번치와 번들을 볼 수 있어요.」와
「비공개 / 팔로우를 승인한 번치만 우리 번치와 번들을 볼 수 있어요.」를 표시한다.
비공개에서 공개를 선택했을 때만
「* 팔로워에게만 공개되던 번들을 누구나 볼 수 있게 되며, 대기 중인 팔로우 요청은 모두 승인돼요.」를 표시한다.
별도 확인 모달 없이 프로필 저장 시 반영한다.

- **비공개 → 공개:** 유효한 대기 요청을 모두 승인하며 이후 팔로우는 즉시 승인한다.
- **공개 → 비공개:** 기존 승인 팔로워는 유지하고 신규 요청만 승인 절차를 거친다.
- 개별 번들의 공개 범위는 바꾸지 않는다. 번들 비공개는 항상 내부 멤버 전용이다.
  번들 공개는 공개 번치면 외부에, 비공개 번치면 승인 팔로워에만 노출한다. 차단 제한을 우선 적용한다.
- 서버가 공개 전환과 요청 접수를 순서대로 처리한다. 전환 전 대기 요청이 남거나 전환 후 신규 요청이 대기로 남는 틈이 없어야 한다.
  차단·취소·이미 처리된 요청을 되살리지 않는다. 자동 승인도 승인 알림의 중복 방지 규칙을 적용한다.

「공개 범위」 라벨 아래 카드를 세로로 두고 카드 전체를 선택 영역으로 쓴다. 공개 카드 아래에는 공개 전환 안내를 표시한다.

<a id="bunch-5-5-5"></a>
### 5.5.5 프로필 저장하기

기능 ID: `BUNCH-08`.

변경 없음·원래 값으로 복원·필수 입력 무효일 때 「저장하기」는 비활성이다.
이미지·이름·소개·공개 범위 중 유효한 변경이 있으면 활성화하며 요청 중 로딩·연타 방지를 적용한다.
이미지 유지·교체·기본 이미지 적용을 구분하고 프로필 전체와 공개 전환 효과를 원자적으로 저장한다.
권한·입력·이름 유일성·조회한 버전을 서버가 검증한다. 다른 기기 변경을 조용히 덮어쓰지 않으며
버전 충돌은 최신 상태 확인 후 다시 저장하도록 API 계약에서 구분한다.

성공 시 「번치 프로필을 수정했어요.」를 표시하고 편집 화면에 남는다. 저장한 값을 새 기준으로 삼아 버튼을 비활성화한다.
홈·전환 목록의 이름·이미지, 홈의 소개·공개 범위를 반영하며 다른 멤버는 재진입·새로고침 때 갱신한다.
같은 요청 키 재시도는 저장과 공개 전환 알림·승인 효과를 한 번만 반영한다.
이름 선점은 「이미 사용 중인 번치 이름이에요」와 저장 비활성, 일반 실패는 공통 토스트·입력 유지·버튼 복구다.
이미지 변경만 먼저 확정하거나 필수 저장 실패를 기본 이미지 성공으로 대체하지 않는다. 권한 상실은 편집 진입 절의 예외를 따른다.

## 5.6 멤버 관리

<a id="bunch-5-6-1"></a>
### 5.6.1 멤버 관리 화면 구성

기능 ID: `MEMBER-07`.

뒤로가기·번치 이름·「+ 멤버 초대」 헤더, 「멤버 N/8명」·「역할별 권한보기 >」,
세로 멤버 카드를 표시한다. 카드는 사진·닉네임이며 본인은 「(나)」를 붙인다.
메인 관리자는 노란 왕관, 공동 관리자는 회색 왕관, 일반 멤버는 배지가 없다.
서버는 메인 관리자 → 공동 관리자 → 일반 멤버 순, 역할 안에서는 닉네임 오름차순으로 제공한다.
메인 관리자는 1명, 공동 관리자는 여러 명, 활성 정원은 8명이다.

| 보는 사람·대상 | 더보기 모달의 버튼(마지막은 취소) |
| --- | --- |
| 메인 관리자 → 일반 멤버 | 공동 관리자로 지정하기 / 관리자 권한 넘기기 / 번치에서 내보내기 / 취소 |
| 메인 관리자 → 공동 관리자 | 공동 관리자 해제하기 / 관리자 권한 넘기기 / 번치에서 내보내기 / 취소 |
| 공동 관리자 → 일반 멤버 | 번치에서 내보내기 / 취소 |
| 본인 카드·공동 관리자가 보는 관리자 카드·일반 멤버가 보는 모든 카드 | 더보기 없음 |

모달 위에는 대상 사진·닉네임을 보여주며 취소·바깥 탭은 닫기만 한다. 정원 8명이어도 초대 버튼은 유지하고 참여 때 차단한다.
관리 요청은 번치 단위로 순서대로 처리하며 실행자·대상 Membership과 현재 역할을 재검증한다.
내 권한 상실은 「권한이 변경되어 해당 기능을 이용할 수 없어요.」 후 더보기 메뉴로,
대상 역할 변경은 「멤버의 역할이 변경되었어요. 다시 확인해 주세요.」 후 더보기 메뉴로 돌아간다.
목록 로딩 실패는 공통 토스트다.

헤더 왼쪽은 뒤로가기·번치 이름, 오른쪽은 초대다. 인원 수 왼쪽/권한보기 오른쪽, 사진 오른쪽 아래 역할 배지, 카드 오른쪽 더보기를 둔다. 관리 모달의 행동 버튼은 세로로 배치한다.

<a id="bunch-5-6-2"></a>
### 5.6.2 역할별 권한 안내 화면

기능 ID: `MEMBER-07`.

멤버 관리의 「역할별 권한보기 >」 또는 역할 변경 알림(11·12·13번)에서 진입하는 서버 호출 없는 앱 고정 안내다.
헤더 왼쪽 뒤로가기는 멤버 관리에서 왔으면 멤버 관리, 앱 내 알림에서 왔으면 알림 목록으로 돌아간다.
실행 중 같은 번치의 푸시로 왔으면 직전 화면, 다른 번치로 전환됐거나 앱을 새로 실행했으면 해당 번치 메인으로 돌아간다.
「기호 안내」는 노란 왕관 메인 관리자·회색 왕관 공동 관리자·연필 번들 최초 생성자,
○ 모두 허용·△ 일부 허용*·✕ 권한 없음이다. 안내 맨 아래에 「*해당 번들에 참여한 경우에만 할 수 있어요.」를 한 번 표시한다.

번치 표는 「번치 정보 바꾸기」·「공동 관리자 지정・해제」·「번치 삭제」는 메인만,
「멤버 내보내기*」·「타멤버 사진 삭제・날짜 변경」·「다른 번치 차단」은 두 관리자에게 ○로 표시한다.
「*메인 관리자는 내보낼 수 없어요.」와 공동 관리자는 일반 멤버만 내보낼 수 있다는 제한을 함께 안내한다.
번들 표는 「번들 업로드」·「멤버 내보내기*」·「작성 중인 번들 삭제」에 두 관리자 △, 최초 생성자 ○,
「발행된 번들 수정・삭제」는 메인만 ○다. 번들 표의 멤버 내보내기는 초안 참여 제외를 뜻한다.
각 표 아래에 각각 메인/최초 생성자를 내보낼 수 없다는 위 주석을 표시하고 △ 조건 설명을 표마다 반복하지 않는다.
번들 표 아래 문구는 「*번들 최초 생성자는 내보낼 수 없어요.」다.
이 표는 본문 권한 기준표와 같아야 하며 최초 생성자의 발행본 권한을 별도로 부여하지 않는다.

<a id="bunch-5-6-3"></a>
### 5.6.3 공동 관리자로 지정하기

기능 ID: `MEMBER-10`.

메인 관리자가 일반 멤버를 선택하면 「{닉네임}님을 공동 관리자로 지정할까요?」 /
「번치를 함께 관리할 수 있어요.」 / 「완료 / 취소」를 표시한다.
완료 시 서버가 활성 소속과 두 사람의 역할을 재확인하고 `MEMBER → CO_OWNER`로 변경한다.
수의 별도 상한은 없으며 번치 정원 안에서 여러 명을 지정할 수 있다.

성공 시 화면에 남아 회색 왕관과 정렬을 갱신하고 「{닉네임}님이 공동 관리자가 되었어요.」를 표시한다.
지정된 회원에게 알림을 보낸다. 권한은 즉시 유효하고 일반 화면은 재진입·새로고침, 공동 편집은 즉시 반영한다.
대상이 이미 나갔으면 변경하지 않고 공통 토스트 후 목록 재조회. 권한·역할 변경은 멤버 관리 공통 예외를 따른다.
취소는 변경 없이 모달만 닫는다.

갱신 전에 권한 없는 행동을 요청하면 서버 거부→오류 토스트→화면 재조회로 복구한다.

<a id="bunch-5-6-4"></a>
### 5.6.4 공동 관리자 권한 해제

기능 ID: `MEMBER-10`.

메인 관리자만 대상 사진과 「{닉네임}님의 공동 관리자 권한을 해제할까요?」 /
「해제 시 일반 멤버로 바뀌어요.」 / 「해제하기 / 취소」를 연다.
서버가 `CO_OWNER → MEMBER`로 변경한다. 메인 관리자 해제는 이 기능으로 할 수 없다.
다른 공동 관리자는 해제할 수 없으며 공동 관리자가 메인 관리자를 해제할 수도 없다.

성공 시 화면 유지·왕관 제거·재정렬과 「{닉네임}님의 공동 관리자 권한을 해제했어요.」를 표시하고 대상자에게 알린다.
권한은 즉시 철회하며 공동 편집에도 반영한다. 대상 이탈·이미 해제는 공통 토스트 후 재조회,
관찰한 역할과 달라진 경우 멤버 관리의 역할 충돌 안내를 따른다. 취소는 변경하지 않는다.

확인 모달 위쪽에 대상 사진을 둔다. 일반 화면은 재진입·새로고침으로 권한을 갱신하고, 갱신 전 권한 없는 요청은 거부→오류 토스트→재조회한다.

<a id="bunch-5-6-5"></a>
### 5.6.5 번치에서 내보내기

기능 ID: `MEMBER-09`.

메인 관리자는 공동 관리자·일반 멤버를, 공동 관리자는 일반 멤버만 내보낼 수 있다.
메인 관리자·본인을 내보낼 수 없다. 「{닉네임}님을 {번치 이름}에서 내보낼까요?」 /
「{닉네임}님이 올린 사진은 사진함에서 삭제되고, 발행된 번들에만 남아요.」 / 「내보내기 / 취소」를 표시한다.

서버는 대상 참여 회차를 종료하고 다음을 같은 업무 트랜잭션으로 처리한다.

- 역할·대상 재확인 후 Membership을 내보내짐으로 종료하며 공동 관리자 권한도 제거한다.
- 업로더 연결을 제거한다. 공동 업로드 사진은 그 회원의 배지만 빼고, 마지막 업로더가 없으면 사진함 Photo를 삭제한다.
  발행본이 참조하는 이미지·기록은 보존한다.
- 초안 참여·코멘트·편집권을 제거하고 생성자 초안은 삭제한다. 사진 0장이 된 초안도 삭제한다.
- 유효 초대 링크·코드를 교체해 이전 초대를 무효화한다. 새 유효 초대를 받으면 일반 멤버로 재참여할 수 있다.
  이전 공동 관리자 권한은 복구하지 않는다. 기록 표시 복구는 5.8.1의 재참여 규칙을 따른다.
- 대상자의 접근 불가 안내와 푸시 전송 대기를 남기고 열린 공동 편집의 접근을 종료한다.

성공 시 목록에서 제거·인원 갱신하고 「{닉네임}님을 번치에서 내보냈어요.」를 표시한다.
앱 내 알림은 생성하지 않는다. 취소는 닫기만 한다. 대상이 이미 나갔으면 공통 토스트 후 재조회한다.
역할이 바뀌었으면 멤버 관리 공통 예외를 따른다. 도중 정리 실패는 전체 롤백하며 대상 접근만 먼저 끊고 데이터를 남기지 않는다.

<a id="bunch-5-6-6"></a>
### 5.6.6 멤버 초대

기능 ID: `MEMBER-01`.

모든 역할이 멤버 관리 헤더 또는 더보기 메뉴에서 초대 화면을 연다.
기존 온보딩의 링크 발급·복사·공유·만료·오류를 재사용하며 유효 초대는 번치당 1개, 만료는 7일이다.
헤더는 X 대신 뒤로가기로 진입 화면에 돌아가고 「나중에 할게요」를 숨긴다.
정원 여부는 실제 참여 때 서버가 판단한다. 내보내기로 교체된 옛 초대는 재사용할 수 없다.

<a id="bunch-5-6-7"></a>
### 5.6.7 관리자 권한 넘기기

기능 ID: `MEMBER-11`.

메인 관리자가 일반·공동 관리자 중 후임을 선택하면 사진과 「{닉네임}님에게 관리자 권한을 넘길까요?」 /
「넘긴 뒤에는 일반 멤버로 번치에 남아요.」 / 「완료 / 취소」를 표시한다.
대상 승격과 본인의 일반 멤버 전환을 원자적으로 처리한다. 대상이 공동 관리자였어도 메인이 되고 다른 공동 관리자는 유지한다.
메인 관리자가 0명 또는 2명인 결과를 커밋하지 않으며 동일 요청 재생은 한 번만 반영한다.

성공 시 멤버 관리에 남아 「{닉네임}님에게 관리자 권한을 넘겼어요.」를 표시한다.
왕관·정렬을 바꾸고 본인에게 보이던 모든 관리 더보기를 숨긴다. 새 메인 관리자에게 알린다.
바뀐 권한은 서버·공동 편집에 즉시 적용하고 다른 화면은 재진입·새로고침으로 갱신한다.
다시 관리하려면 새 메인 관리자의 공동 관리자 지정 또는 재인계가 필요하다.
취소·바깥 탭은 변경하지 않는다. 대상 이탈은 공통 토스트 후 재조회, 역할 경합은 공통 역할 변경 안내다.
확정 실패면 두 역할 모두 유지한다. 응답 유실이면 같은 요청 키로 결과를 확인하고 중복 인계하지 않는다.

## 5.7 차단 목록

확인 모달 위쪽에 대상 사진을 둔다. 갱신 전에 권한 없는 행동을 요청하면 서버 거부→오류 토스트→화면 재조회로 복구한다.

<a id="bunch-5-7-1"></a>
### 5.7.1 차단 목록 화면

기능 ID: `FEED-08`.

모든 역할이 같은 번치 명의 차단 목록을 본다. 뒤로가기는 더보기로 돌아가고 「차단된 번치 N개」 아래
사진·이름·「차단해제」를 최근 차단순으로 표시한다. 해제 버튼은 두 관리자에게만 보인다.
상대만 우리를 차단한 관계는 목록에 넣지 않으며 삭제된 대상은 제외한다.
0개면 「아직 차단한 번치가 없어요」 /
「차단은 번치 멤버 모두에게 적용되며, 서로의 번들・프로필・댓글은 보이지 않아요.」를 표시한다.
빈 상태 이미지는 디자인 대기다. 조회 실패는 공통 토스트다.

왼쪽 뒤로가기는 더보기로 돌아간다. 행 오른쪽에 차단해제 버튼을 두며 빈 상태에는 누를 수 있는 항목이 없다.

<a id="bunch-5-7-2"></a>
### 5.7.2 차단 해제

기능 ID: `FEED-08`.

관리자만 「{번치 이름} 차단을 해제할까요?」 /
「서로의 번들과 프로필을 볼 수 있어요. 팔로우는 자동으로 돌아오지 않아요.」 / 「해제하기 / 취소」를 연다.
서버는 현재 권한과 **우리 번치가 설정한 차단**을 해제한다. 상대의 별도 차단은 해제하지 않는다.
양방향 중 어느 차단이라도 남으면 노출 제한은 유지하며, 모두 풀려도 현재 공개 범위·팔로우 조건을 다시 적용한다.
이전 팔로우·요청은 복구하지 않는다.

성공 시 모달을 닫고 목록에서 제거·개수 갱신, 「{번치 이름} 번치를 차단 해제했어요.」를 표시한다.
마지막 행이면 빈 상태로 바꾼다. 다른 관리자가 먼저 해제해도 성공으로 취급한다.
실패는 공통 토스트 후 목록 유지, 취소는 변경하지 않는다. 역할 상실 시 서버가 거부한다.

## 5.8 번치 나가기

확인 모달 위쪽에 대상 번치 프로필 이미지를 둔다. 취소하면 모달만 닫고 기존 화면을 유지한다.

<a id="bunch-5-8-1"></a>
### 5.8.1 번치 나가기(일반 멤버·공동 관리자)

기능 ID: `MEMBER-08`.

「{번치 이름} 번치를 나갈까요?」 /
「사진함에 직접 올린 사진은 삭제되지만, 이미 발행된 번들의 사진은 그대로 남아요.」 / 「취소 / 나가기」를 연다.
공동 관리자는 인계 없이 나간다. 취소·바깥 탭은 변경하지 않는다.
직접 나간 회원도 유효한 초대와 새 참여 요청 키로 같은 번치에 재참여할 수 있다. 예전 성공 요청의 재생은 재참여가 아니다.

서버는 해당 Membership을 종료하고 업로더 연결·초안 참여·본인 초안 코멘트·편집권을 같은 트랜잭션에서 정리한다.
공동 업로더가 남은 Photo는 본인 배지만 제거하고, 마지막 업로더가 없어지면 사진함에서 삭제한다.
발행본 사진·기여 기록은 유지하며 나간 사람의 발행 코멘트 내용도 유지한다.
생성자 초안은 삭제하고 다른 초안은 본인 참여를 제거한다. 그 결과 사진 0장이면 해당 초안도 삭제한다.
발행본 작성자 표시는 기존의 「나간 멤버」 규칙을 따르며 번치 나가기가 개인 계정 삭제를 뜻하지 않는다.

**재참여 복구(직접 나가기·내보내짐 공통):** 같은 개인 계정으로 유효한 초대를 확인하고 정원·소속 한도 안에서
새 Membership을 만든다. 역할은 항상 MEMBER이며 이전 메인·공동 관리자 권한을 자동 복구하지 않는다.
남아 있는 발행본의 동일 memberId 기여·코멘트는 현재 닉네임·프로필로 다시 표시한다. 내용이나 기여 행을 복제하지 않는다.
본인 코멘트 수정은 현재 소속·작성자라는 기존 조건을 다시 적용한다.
이미 삭제된 사진함 Photo·업로더 연결·초안·초안 코멘트·편집권은 복구하지 않고, 다른 멤버가 유지한 사진에도 과거 업로더 배지를 자동 복원하지 않는다.
내보내짐 안내와 그 안내의 미전송 푸시 작업은 재참여 트랜잭션에서 제거·취소한다. 재참여는 기존 새 멤버 참여 알림만 생성한다.
서비스 탈퇴 후 새 계정으로 가입하는 경우에는 과거 계정과 연결하지 않는 기존 계약을 유지한다.

완료 즉시 접근을 종료하고 전환 목록에서 제거한다. 남은 멤버에게 나가기 알림은 보내지 않으며
본인 tombstone도 만들지 않는다. 같은 요청 재생은 한 번만 처리한다.
업로드 도중 이탈이면 앱은 남은 업로드를 멈추고 서버는 종료된 소속의 후속 업로드를 거부한다.
먼저 성공한 업로드도 동일한 업로더 정리에 포함한다. 정리 실패면 전체 롤백·공통 토스트 후 기존 번치 유지다.

취소·바깥 탭은 모달만 닫고 기존 화면을 유지한다.

<a id="bunch-5-8-2"></a>
### 5.8.2 메인 관리자 나가기(새 관리자 지정)

기능 ID: `MEMBER-11`.

**번치 나가기에서는 후임 직접 선택이 필수다.** 공동 관리자가 있어도 자동 선택하지 않는다.
뒤로가기·「관리자 권한을 넘길 멤버를 정해주세요.」 / 「선택한 멤버가 새로운 관리자가 돼요.」 아래
본인을 제외한 일반·공동 관리자 카드 중 1명을 고른다. 선택 전 「관리자로 지정하기」는 비활성이다.

선택 후 확인 시트는 「{닉네임}님을 관리자로 지정하고 나갈까요?」 /
「{닉네임}님이 번치의 모든 관리 권한을 갖게 돼요.」 /
「사진함에 직접 올린 사진은 삭제되지만, 이미 발행된 번들의 사진은 그대로 남아요.」 /
「취소 / 지정하고 나가기」다. 취소하면 선택을 유지한다.
서버는 후임의 현재 Membership·역할을 검증하고 승격·본인 소속 종료·사진·초안 정리를 원자적으로 처리한다.
다른 공동 관리자는 유지하며 새 메인 관리자에게 알린다.
성공 시 「{닉네임}님을 관리자로 지정하고 나왔어요.」 후 남은 번치로 이동한다.

대상 이탈은 「일시적인 오류가 발생했어요. 다시 시도해 주세요.」 후 선택 해제·버튼 비활성·목록 갱신이다.
혼자라면 지정 화면 대신 「혼자 있는 번치는 나갈 수 없어요」 /
「번치를 더 쓰지 않는다면 번치를 삭제해 주세요.」 / 「취소 / 번치 삭제하기」로 삭제 안내에 연결한다.
실패 시 화면과 기존 역할을 유지하고 공통 토스트를 표시한다.

**계정 탈퇴와의 경계:** 서비스 탈퇴는 기존 자동 승계 기준을 유지한다.
남은 활성 멤버 중 ① 발행 번들 Contributor 횟수 많은 순 ② 사진 업로드·초안 편집·코멘트 작성의 최근 활동순
③ 번치 가입일 빠른 순으로 후임을 고른다. 완전 동률이면 API 계약의 소속 ID 오름차순으로 결정한다.
단순 접속은 최근 활동에 넣지 않는다.
사전 안내와 실제 처리 때 결과가 달라지면 재확인하는 기존 요구를 유지하며, 혼자인 번치는 계정 탈퇴와 함께 삭제한다.
이 자동 알고리즘을 일반 나가기의 대체 경로로 노출하지 않는다. 계정 익명화의 구체 계약은 계정 탈퇴 범위에서 확정한다.

왼쪽 뒤로가기는 더보기로 돌아간다. 세로 멤버 카드에 사진·닉네임·오른쪽 선택 원을 두고 다른 카드를 선택하면 선택을 옮겨 표시한다. 하단 「관리자로 지정하기」는 아래에서 확인 시트를 올린다.

<a id="bunch-5-8-3"></a>
### 5.8.3 번치 나간 뒤 이동

기능 ID: `MEMBER-08`, `BUNCH-05`.

다른 활성 소속이 있으면 가장 최근 사용한 번치 홈으로, 없으면 번치 없음 화면으로 이동한다.
도착한 번치를 마지막 사용 번치로 저장하고 헤더·데이터·행동 명의를 전환한다.
일반·공동 관리자는 「{번치 이름} 번치를 나왔어요.」, 메인은 「{닉네임}님을 관리자로 지정하고 나왔어요.」를 표시한다.
도착 홈 조회가 실패해도 이미 완료된 나가기를 되돌리지 않으며 공통 토스트 후 새 도착지 조회만 재시도한다.

## 5.9 번치 삭제

<a id="bunch-5-9-1"></a>
### 5.9.1 번치 삭제 안내

기능 ID: `BUNCH-09`.

메인 관리자만 진입한다. 뒤로가기는 더보기로 돌아가며 「{번치 이름}을 삭제할까요?」 아래
「사진함 속 사진 / 작성 중이거나 발행된 번들 / 팔로우・좋아요・댓글」을 삭제 항목으로 안내한다.
「번치를 삭제하면 모든 활동 내역이 영구적으로 삭제되며, 어떠한 경우에도 복구할 수 없어요.」를 표시한다.
「다음」은 확인 화면으로 이동할 뿐이며 이 화면 진입·다음 탭으로 삭제하지 않는다.

왼쪽 뒤로가기는 더보기로, 「삭제되는 항목」 상자 아래 하단 「다음」은 확인 화면으로 이동한다.

<a id="bunch-5-9-2"></a>
### 5.9.2 번치 삭제 확인(문구 입력)

기능 ID: `BUNCH-09`.

「정말 삭제할까요?」 / 「확인을 위해 아래에 '삭제하기'를 입력해주세요.」 아래
「확인 문구 입력」, placeholder 「삭제하기」와 「*‘삭제하기’를 정확히 입력하면 삭제 버튼이 활성화돼요.」를 둔다.
삭제할 번치명·소속 멤버 닉네임(본인 「(나)」)을 함께 보여준다. 뒤로가기는 삭제 안내로 돌아간다.
입력값 앞뒤 공백을 제거한 결과가 정확히 「삭제하기」일 때만 버튼을 활성화한다.
누르면 로딩·연타 차단하며 서버도 확인 문구·현재 메인 관리자·대상 버전을 검사한다.

번치 프로필·사진함·추천 후보·초안·발행본(캡션·코멘트 포함)·초대와
양방향 팔로우·좋아요·댓글·신고·차단 관계·피드 노출을 영구 제거한다.
활성 접근을 즉시 종료하며 물리 이미지 파일 정리는 커밋 이후 별도 처리할 수 있다.
삭제 전 이미지 참조·알림 수신자·이름을 확보하고, 다른 참조가 있는 자산을 잘못 지우지 않는다.
단순 DB cascade만으로 편집 연결 종료·이미지 정리·접근 불가 안내·푸시 생성이 모두 수행된다고 가정하지 않는다.

동일 요청 키 재시도는 중복 삭제·알림을 만들지 않는다. 문구 불일치는 실행하지 않고 버튼을 비활성화한다.
메인 관리자 상실은 공통 토스트 후 홈으로, 확정 실패는 화면 유지·공통 토스트다.
응답 유실은 같은 키로 완료 결과를 확인한다. 삭제 중 일부 데이터만 제거한 결과를 성공으로 응답하지 않는다.

「삭제할 번치 정보」 상자에는 「번치명: {번치 이름}」·「소속 멤버: {닉네임 목록}」을 표시한다. 실행 버튼 「삭제하기」는 하단에 두며 입력란 탭은 키보드를 열고 빈 곳·버튼 탭은 닫는다.

<a id="bunch-5-9-3"></a>
### 5.9.3 번치 삭제 후 처리·알림

기능 ID: `BUNCH-09`, `NOTI-02`.

삭제 실행자는 「{번치 이름} 번치를 삭제했어요.」 후 남은 최근 번치 홈 또는 번치 없음 화면으로 이동한다.
전환 목록에서는 즉시 제거하고 실행자 접근 불가 안내는 만들지 않는다. 새 도착지를 마지막 사용 번치에 반영한다.

삭제 시 남아 있던 다른 멤버에게는 제목 「[{번치 이름}] 번치가 삭제됐어요」 /
설명 「관리자가 번치를 영구 삭제했어요.」의 **푸시만** 보낸다.
앱 안에서는 전환 목록의 접근 불가 안내로 알린다. 열려 있던 홈·공동 편집 등은 다음 정보 조회·화면 이동·새로고침·앱 복귀에서
삭제를 확인하며 기존 삭제 모달의 확인 후 남은 최근 번치 또는 0개 화면으로 이동한다.
번치와 함께 삭제되지 않는 안내·전송 대기를 별도로 남긴다. 푸시 권한 거부·전송 실패에도 안내는 조회할 수 있어야 한다.

## 5.10 다른 번치 프로필·소셜 행동

<a id="bunch-5-10-1"></a>
### 5.10.1 다른 번치 프로필 화면(공개 번치)

기능 ID: `FEED-02`.

피드의 번치 이름·팔로워/팔로잉 행에서 진입한다. 헤더는 뒤로가기·더보기만 두고 전환·알림은 두지 않는다.
뭉치·이름·소개·팔로워/팔로잉/멤버 수·전체 폭 팔로우 버튼 아래에 번들을 3열 그리드로 표시한다.
내부의 번들 탭·번들 수 제목·가볼 곳 버튼·번들 생성 「+」·사진함은 외부에 보여주지 않는다.
카드 탭은 상세, 팔로워·팔로잉·멤버 수는 해당 목록으로 이동한다.

서버는 대상 번치의 **발행된 공개 번들만** 목록·상세로 반환한다. 외부 프로필의 뭉치 단계는 내부와 같은
전체 발행 수 기준이다. 단계로 활동량을 추정할 수는 있지만 비공개 번들 개수·내용을 직접 반환하지 않는다.
차단·공개 범위·승인 관계는 매 요청 검사한다.
차단 관계면 접근 제한 화면이다.

회원이 대상 번치에도 속해 있더라도 현재 번치와 다르면 동일한 외부 범위로 조회한다.
현재 번치 명의 팔로우·차단·신고를 허용하며, 대상의 내부 멤버 권한으로 조회 범위를 넓히지 않는다.
대상이 현재 번치 자신이면 내부 홈으로 이동하며 자기 팔로우·차단·신고를 금지한다.
로딩 실패는 공통 토스트다. 삭제 대상은 「삭제된 번치예요.」 후 이전 화면 복귀라는 **원문 제안**을 유지하며
구현 전 API·화면의 확정 오류 처리에 반영 여부를 결정한다.

<a id="bunch-5-10-2"></a>
### 5.10.2 다른 번치 프로필 화면(비공개 번치)

기능 ID: `FEED-02`.

기본 프로필·팔로우 버튼은 공개 화면과 같고 이름에 자물쇠를 붙인다.
미승인 상태는 이름·실제 단계의 뭉치·소개·팔로워/팔로잉/멤버 수까지만 보여준다.
번들 수·본문·멤버 명단·팔로워/팔로잉 목록은 제공하지 않는다.
「비공개 번치예요」 / 「번들을 보려면 이 번치를 팔로우하세요.」로 그리드를 대체하고
세 가지 수를 눌러도 목록으로 이동하지 않는다.

요청 전 「팔로우」, 대기 중 「팔로우 요청됨」, 승인 후 「팔로잉 ∨」다.
승인된 현재 번치는 공개 프로필과 같은 범위의 공개 발행본·외부 멤버·관계 목록을 본다.
대상 번치의 비공개 발행본·사진함·초안은 여전히 비노출이다.
승인·공개 전환은 다음 진입·새로고침 때 반영한다. 공개 전환은 유효 대기 요청을 자동 승인한다.

<a id="bunch-5-10-3"></a>
### 5.10.3 팔로우·팔로우 요청·팔로우 취소

기능 ID: `FEED-03`.

우리 번치 멤버 누구나 현재 번치 명의로 행동하며 실행 멤버는 외부에 표시하지 않는다.
공개 대상의 「팔로우」는 즉시 승인·「팔로잉 ∨」로 바꾸고 「{번치 이름} 번치를 팔로우했어요.」를 표시한다.
비공개 대상은 요청 생성 후 「팔로우 요청됨」으로 바꾸며 상대에게 새 요청을 알린다.

「팔로잉 ∨」는 대상 사진·이름·공개/비공개 표시와 「취소 / 팔로우 취소」 시트를 연다.
완료하면 「팔로우」로 바꾸고 「팔로우를 취소했어요.」를 표시한다. 비공개 대상의 본문은 다시 숨긴다.
「팔로우 요청됨」은 대상 사진·이름·「요청 대기 중인 비공개 번치」·「취소 / 팔로우 요청 취소」를 열고,
완료 시 「팔로우 요청을 취소했어요.」를 표시한다. 취소·바깥 탭·아래로 끌기는 상태를 유지한다.
시트 도중 승인됐다면 요청 취소 동작으로 **이미 승인된 팔로우를 취소**하고 토스트도 「팔로우를 취소했어요.」로 바꾼다.

서버는 방향별 번치 쌍에 하나의 유효 관계만 유지하고 중복 요청·연타로 중복 관계·알림을 만들지 않는다.
상대가 누구든 우리 번치의 다른 멤버도 승인·취소된 상태를 공유한다. 변경 수치를 즉시 갱신하되 대기 요청은 팔로워에 세지 않는다.
차단이면 생성하지 않고 접근 제한 화면, 네트워크 실패면 공통 토스트 후 버튼을 기존 상태로 복구한다.

팔로우 버튼은 채워진 형태다. 취소 시트는 아래에서 올라오며 위에서 사진→이름→「공개 번치 / 비공개 번치」 또는 요청 대기 안내 순이다. 요청 취소 성공 시 시트를 닫고 버튼을 「팔로우」로 되돌린다.

<a id="bunch-5-10-4"></a>
### 5.10.4 다른 번치 더보기(차단하기·신고하기)

기능 ID: `FEED-07`, `FEED-08`.

다른 번치 프로필의 더보기 시트는 두 관리자에게 「차단하기 / 신고하기 / 취소」,
일반 멤버에게 「신고하기 / 취소」를 표시한다. 바깥 탭·취소는 닫기만 한다.
서버는 차단에는 현재 관리자 역할을, 신고에는 활성 소속을 검사한다.
대상도 소속 번치인 경우라도 현재 번치와 다르면 이 권한으로 행동할 수 있다.

<a id="bunch-5-10-5"></a>
### 5.10.5 번치 차단하기

기능 ID: `FEED-08`.

관리자가 대상 사진과 「{번치 이름} 번치를 차단할까요?」 /
「차단하면 번치의 모든 멤버가 서로의 활동을 볼 수 없어요.」 / 「취소 / 차단하기」를 연다.
성공 시 「{번치 이름} 번치를 차단했어요.」 후 이전 화면으로 돌아간다.

차단 설정은 우리 → 상대 방향의 관계로 저장하지만 어느 한쪽 차단만 있어도 노출 제한은 **양방향**이다.
서로의 피드·프로필·번들 상세·댓글·좋아요·팔로워/팔로잉 목록을 숨기고 좋아요·댓글·팔로우를 거부한다.
양쪽 팔로우와 대기 요청은 함께 삭제하며 해제해도 되살리지 않는다.
기존 댓글은 차단만으로 영구 삭제하지 않고 조회에서 숨긴다. 차단을 모두 해제하면 현재 노출 조건에 따라 다시 보인다.
차단 사실은 상대에게 알리지 않고 우리 차단 목록에만 기록한다. 두 번치에 속한 회원도 각 현재 번치의 차단 문맥을 적용하며
실제로 해당 번치로 전환한 뒤 보는 내부 사진함·초안·발행본에는 외부 차단 제한을 적용하지 않는다.

실패는 공통 토스트 후 확인 시트 유지, 권한 상실은 같은 토스트 후 시트를 닫는다.
취소는 변경하지 않는다. 동일 차단 중복은 관계·팔로우 정리를 반복 생성하지 않는다.

차단 확인 시트는 아래에서 올라오며 위쪽에 대상 번치 프로필 이미지를 표시한다.

<a id="bunch-5-10-6"></a>
### 5.10.6 차단된 번치에 들어갔을 때

기능 ID: `FEED-08`.

과거 알림·새로고침 전 목록으로 접근해도 현재 차단을 서버가 검사한다.
뒤로가기만 있는 「볼 수 없는 번치예요」 / 「해당 번치의 프로필 정보를 불러올 수 없어요.」 화면을 표시한다.
프로필·번들·행동 버튼을 내려주지 않고 차단한 쪽이 누구인지 밝히지 않는다.
우리 또는 상대가 차단한 경우 모두 같으며 뒤로가기는 진입 화면으로 돌아간다.

<a id="bunch-5-10-7"></a>
### 5.10.7 번치 신고하기

기능 ID: `FEED-07`.

「{번치 이름} 번치를 신고해요」 / 「현재 활동 번치: {내 현재 번치 이름}」 아래
「스팸 / 음란・부적절한 내용 / 괴롭힘・욕설 / 개인정보 노출 / 기타」 중 1개를 고른다.
기타는 「상세 사유 *」와 「신고 이유를 입력해주세요.」 입력을 추가하며 공백만은 빈 값으로 본다.
사유 미선택은 버튼 비활성, 기타 외 사유는 즉시 활성, 기타(`OTHER`)는 유효 상세 1~200자를 요구한다.
서버도 같은 조건을 검증하고 현재 번치 명의 접수와 실행 회원의 내부 기록을 구분한다.

성공은 「신고가 접수됐어요.」 후 시트를 닫고 대상 콘텐츠를 **신고한 현재 번치의 피드에서 제외**한다.
다른 소속 번치로 전환하면 그 번치 문맥으로 판단한다. 반복 신고도 접수 성공으로 응답하되
운영 검토는 신고 번치·대상 번치 쌍당 한 건으로 중복 집계한다. 멤버별 신고를 별도 건수로 부풀리지 않는다.
운영 검토 후 숨김·삭제·이용 정지는 운영 기능이며 누적 건수만으로 자동 숨김을 확정하지 않는다.
취소(끌기·바깥 탭)는 접수하지 않는다. 실패는 공통 토스트 후 사유·상세를 유지한다.

더보기·신고 시트는 아래에서 올라온다. 기타 상세 입력은 사유 아래에, 신고 실행 버튼은 하단에 둔다.

<a id="bunch-5-10-8"></a>
### 5.10.8 다른 번치 멤버 목록

기능 ID: `FEED-02`.

공개 대상 또는 승인된 팔로워가 보는 비공개 대상의 멤버 수에서 진입한다.
사진·닉네임·**공개 역할 배지**만 제공하며 노란 왕관은 메인, 회색 왕관은 공동 관리자다.
내부 목록과 같은 역할 우선·닉네임 오름차순으로 정렬한다.
뒤로가기만 두고 카드 탭 동작·관리 더보기·인원/8명·권한 안내·초대는 없다.
출생연도·성별 등 다른 개인 정보는 제공하지 않는다.

서버는 비공개 승인·양방향 차단을 다시 확인한다. 목록 조회 실패는 공통 토스트,
다음 요청에 차단이 확인되면 접근 제한 화면으로, 비공개 팔로우 취소면 재진입·새로고침 때 대상 프로필로 돌아간다.

## 5.11 팔로워·팔로잉

세로 멤버 카드의 사진 오른쪽 아래에 역할 배지를 둔다. 헤더 왼쪽 뒤로가기는 대상 프로필로 돌아간다.

<a id="bunch-5-11-1"></a>
### 5.11.1 팔로워·팔로잉 목록

기능 ID: `FEED-03`.

홈·외부 프로필에서 누른 「팔로워 N / 팔로잉 N」 탭을 선택해 연다.
각 행은 사진·이름·비공개 자물쇠·**내 현재 번치와 행 대상 사이의 관계 버튼**이다.
「팔로우」는 바로 실행, 「팔로잉」은 취소 시트, 「요청됨」은 요청 취소 시트를 연다.
버튼 탭은 화면 이동 없이 상태·관련 수를 갱신하고 행 본문 탭은 대상 프로필로 이동한다.
현재 번치 자신의 행에는 행동 버튼이 없다.

서버는 승인된 관계만 수·목록에 넣고 차단 관계를 제외한다. 조회 대상과의 접근 조건과
현재 번치·각 행 대상 간 차단도 확인한다. 최근 팔로우순으로 페이지 조회하며 스크롤로 이어 불러온다.
자기 번치가 비공개이고 대기 요청이 있으면 팔로워 탭 맨 위 「팔로우 요청 N」을 표시한다.
외부 번치 목록에 그 번치의 대기 요청을 공개하지 않는다. 비공개 대상의 미승인 상태에서는 목록 자체를 열 수 없다.
빈 목록은 비워두며 조회 실패는 공통 토스트다.

위쪽 탭을 누르면 선택 탭과 목록을 바꾸고 뒤로가기는 진입한 프로필로 돌아간다. 관계 버튼은 행 오른쪽에 두며 팔로우는 검정, 팔로잉·요청됨은 회색이다. 취소 시트와 토스트는 5.10.3을 따른다.

<a id="bunch-5-11-2"></a>
### 5.11.2 팔로우 요청 승인·거절

기능 ID: `FEED-03`.

우리 번치의 요청 행에서 진입하며 「대기 중인 요청 N개」 아래 사진·이름·자물쇠·요청 시간과 「승인 / 거절」을 표시한다.
최근 요청순이고 시각은 방금 전 / N분 전 / N시간 전 / N일 전이다.
우리 번치의 모든 멤버가 확인창 없이 승인·거절할 수 있다.
성공은 행 제거·개수 갱신과 「{번치 이름} 번치의 팔로우 요청을 승인했어요.」 또는
「{번치 이름} 번치의 팔로우를 거절했어요.」다. 승인만 요청 번치 멤버에게 알리고 거절은 알리지 않는다.
거절 후 다시 요청할 수 있다.

서버는 요청 회차를 식별하고 첫 처리만 반영한다. 다른 멤버가 이미 승인한 요청에 늦은 거절이 와도
승인을 취소하지 않는다. 이미 처리·요청 취소·요청 번치 삭제면 토스트 없이 행만 제거한다.
재요청으로 생긴 새 요청에 과거 승인·거절을 적용하지 않는다.
팔로워 목록 복귀 시 재조회하고 0건이면 요청 행을 숨긴다. 실패면 공통 토스트 후 행 유지다.
공개 전환 자동 승인·차단과 경합해도 유효 관계와 알림이 한 번만 생성되어야 한다.

승인·거절 버튼은 행 오른쪽에 두고 뒤로가기는 팔로워 목록으로 돌아간다.

## 알림 연계

알림 목록·읽음·이동·21종 문구·수신자와 푸시 정책은 [알림 Spec](notification.md)이 소유한다.
번치는 홈·전환 목록의 미확인 수를 조회하고, 역할·참여·공개 범위·이탈·삭제의 실제 변경 시
[알림 저장 계약](notification-schema.md)에 따라 같은 트랜잭션에서 알림·전송 대기를 연결한다.
접근 불가 안내 자체는 번치 소유이며 내보내짐·삭제 알림의 채널·전송은 알림 도메인에 맡긴다.

## 제안·디자인 대기와 남은 계약

- **원문 제안:** 삭제된 외부 번치 선택 시 「삭제된 번치예요.」 후 복귀.
  확정하지 않은 제안을 외부 오류 계약의 완료 항목으로 처리하지 않는다.
- **디자인 대기:** 뭉치·오브젝트·유형별 단계 리소스·단계 변화 연출, 차단 목록 빈 상태 이미지.
  성장 알림의 존재와 화면 애니메이션의 확정은 별개다. 알림 빈 상태의 디자인은 [알림 Spec](notification.md)을 따른다.
- **상세 계약의 소유 문서:** 번치 페이지·정렬·상태/역할 충돌·버전·요청 키 수명과 재생 검증은
  [번치 API](bunch-api.md)·[번치 스키마](bunch-schema.md)가 소유한다.
  알림 활동 집계·모두 읽음·APNs 등록/재시도는 [알림 API](notification-api.md)·[알림 스키마](notification-schema.md)가 소유한다.
  이것은 제품의 정상·실패 흐름을 미확정으로 되돌리는 항목이 아니다.
- **연결 영역의 미정 보존:** 추천 후보 재계산과 변환 날짜·여행 재제안 억제,
  탈퇴 익명화는 해당 영역에서 정렬한다. 번치 재참여 허용·발행 기록 표시 복구·일반 멤버 시작은 위에서 확정했다.
  이 문서가 계정 삭제를 구현하거나 삭제된 데이터를 복구하는 기능을 추가하는 것은 아니다.
- **기존 문서와의 정렬:** PRD·번들 Spec·온보딩 API 계약도 같은 역할·권한·Stage·알림 정책을 적용한다.
  #32의 최종 병합 API 문서는 구현 착수 때 다시 대조하고 과거 표를 새 정책의 구현 증거로 인용하지 않는다.

## 구현 분할과 완료 조건

### 선행 기반과 단계

1. **문서 계약:** 본 제품 Spec과 API·DB 계약을 함께 검토한다. 문서는 #32 병합 전 작성할 수 있다.
2. **#32 병합 후 역할·권한·단계 정렬:** 최신 `dev`에서 구현 브랜치를 만들고 OWNER 단일성·CO_OWNER를 도입한다.
   기존 여러 Owner 데이터가 있다면 임의 승격·강등하지 않고 사전 점검·전환 기준을 DB 계약에 따라 확정한다.
   이상 데이터면 마이그레이션을 중단하며 적용된 Flyway 파일은 수정하지 않는다.
3. **홈·전환·프로필:** 기존 목록·통계 API를 재사용해 초안 최신 편집순·Stage를 맞추고 역할·권한·최근 사용·일괄 저장을 연결한다.
4. **멤버·이탈·삭제:** #25와 #38 소유 범위를 연결해 역할 인계·사진 업로더·초안·편집권·tombstone을 통합한다.
   이탈 중간 상태가 남지 않게 하며 새 참여 회차를 과거 요청에서 보호한다.
5. **소셜:** 번치 쌍의 팔로우·요청·양방향 차단 효과·신고 중복 검토·외부 노출을 구현한다.
6. **알림 연계:** [알림 Spec](notification.md)의 저장·전송 기반을 먼저 준비하고 각 기능의 실제 변경과 연결한다.
   앞 단계의 알림 생성은 공통 기반 준비 뒤 활성화하며 업무와 전송 대기 간 유실을 허용하지 않는다.
