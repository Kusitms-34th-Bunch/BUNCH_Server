# 공통 금칙어 검사 계약 — 이슈 #161

2026-11-16 승인 추가 명세와 2026-11-17 스케줄러 제거·번치 소개 사전 검증 API 결정을 적용한다.
요구사항 확정과 자동 테스트·실제 앱 검증은 구분한다.

## 목록·비교

- 한국어는 yoonheyjung/badwords-ko의 MIT 목록, 영문은 LDNOOBW의 CC BY 4.0 en 목록을 사용한다.
  고정 커밋·원본 URL·원문 라이선스·변경 표시는 번들된 목록과 출처 문서에 보존한다.
- 외부 JSON 하나의 `base`, `additions`, `exclusions` 배열을 읽는다. 기본+추가−제외이며 제외가 우선한다.
  제외는 정규화 후 같은 항목을 목록에서 해제하는 의미다. 문장 전체를 허용하는 화이트리스트가 아니다.
- 입력과 단어를 NFC·Locale.ROOT 소문자로 변환한 형태, Unicode 문자·숫자·결합기호만 남긴 형태로
  리터럴 부분 일치 검사한다. 제거 후 NFC를 다시 적용한다. 특수문자 전용 단어도 원문 경로로 검사한다.
  이모지의 variation selector는 함께 제거하며 빈 비교 단어는 사용하지 않는다.
  원문 저장 규칙·이름 유일성의 대소문자 구분은 바꾸지 않는다.
- 목록의 자모 표현은 검사하지만 임의 초성 추론·호환 자모 합성·유사문자 치환은 하지 않는다.
  부분 일치는 문맥을 알지 못해 정상 단어에도 걸릴 수 있으며 제외 목록으로 운영한다.
- 서버 기동 시 사전을 한 번 읽고 프로세스 수명 동안 불변 스냅샷으로 사용한다. 외부 경로 미설정 시
  번들 목록을 사용하며, 설정한 외부 경로의 로딩 실패는 기동 실패다. 요청 처리 중 외부 통신은 없다.
- 외부 파일은 디렉터리 단위 읽기 전용 마운트와 원자적 파일 교체를 사용한다. 변경은 서버 재시작 후
  적용되며 앱 업데이트는 필요 없다. 핫 리로드·수동 리로드 API·주기적 파일 확인은 제공하지 않는다.

## 검사 시점·응답

- 닉네임(1.4.4, 7.2.5)·번치 이름(2.2.3, 5.5.3) 중복 확인은 기존 필드와 함께
  `status: AVAILABLE | DUPLICATE | PROHIBITED_WORD`를 반환한다. 금칙어가 중복보다 우선하며
  `available`은 AVAILABLE일 때만 true다. 기존 형식 오류·권한·중복 판단 규칙은 유지한다.
- 가입 완료(1.4.7)·개인 프로필 저장(7.2.7)은 닉네임, 번치 생성(2.2.10)·프로필 저장(5.5.5)은
  이름과 소개를 검사한다.
- 소개(2.2.6, 2.2.8)는 「다음」에서 `POST /api/v1/bunches/introduction-validation`으로 먼저 검사한다.
  인증된 가입 완료 회원이 JSON `{"introduction":"소개"}`를 보내며, 서버는 생성과 같은 형식·금칙어
  규칙을 적용한다. DB 쓰기·중간 저장·요청 키 없이 성공은 HTTP 200/data null, 금칙어는
  HTTP 400 `COMMON_003 / error.prohibited_word`와 `detail.fields:["introduction"]`다.
  [상세 API·오류 계약](login-onboarding-api.md#bunch-introduction-validation)을 따른다.
- 프런트는 「다음」의 최신 입력을 검사하고 해당 입력의 성공 응답에만 이동한다. 금칙어이면
  입력란 아래 빨간색 「사용할 수 없는 단어가 포함되어 있어요」를 표시하고, 수정하면 문구를 지운다.
  검사 중·오류 시 이동하지 않고 재시도를 허용하며 이전 입력의 응답은 무시한다.
  최종 생성(2.2.10)은 사전 검증 우회·이후 입력 변경에도 이름과 소개를 다시 검사한다.
- 이미지 업로드 전 검사하고 DB 반영 직전 현재 서버의 시작 시점 사전으로 재검사한다.
  성공한 멱등 요청 재시도는 기존 응답을 유지한다. 신규 저장은 금칙어가 하나라도 있으면 전체 거부한다.
- 발행본 일괄 수정(6.2.12)은 제출한 제목, 댓글·답글 등록(6.2.8)은 content를 검사한다.
- 거부는 HTTP 400 `COMMON_003 / error.prohibited_word`, detail.fields 문자열 배열이다.
  번들 발행의 코멘트 위반은 fields의 `comments`와 detail.commentMemberIds로 식별한다.
  예: `{"fields":["title","comments"],"commentMemberIds":[123]}`. 적발 단어는 반환하지 않는다.
- 신고 상세 사유·위치·사진 캡션은 검사하지 않는다. 이미 발행된 글은 목록 변경만으로 숨기지 않는다.

## 초안·실시간·발행

- 제목(4.3.3)·멤버 코멘트(4.3.8) 자동 저장은 금칙어가 있어도 허용한다. REST 제목·Automerge
  최종 병합 제목·추천 초안 생성에도 검사 상태를 저장한다. 금칙어 때문에 CRDT 원문을 고치지 않는다.
- 검사 상태는 `profanity: {dictionaryVersion, titleHasProhibitedWord,
  comments:[{memberId, hasProhibitedWord}]}`다. 현재 참여자만 포함한다.
  스냅샷·제목 병합 응답과 TITLE/COMMENT/PARTICIPANTS 이벤트에 추가하고 이벤트의 기존 필드를 보존한다.
  해당 이벤트에는 최신 publishBlockers도 전달한다. 실제 제목·코멘트·참여자 변경 시 내용과 검사
  상태를 같은 트랜잭션에서 저장하고, 커밋 후 응답과 동일한 상태를 기존 이벤트로 전달한다.
- TITLE_PROHIBITED_WORD·COMMENTS_PROHIBITED_WORD를 발행 차단 사유에 추가하고 준비 알림에도 반영한다.
  발행(4.3.12)은 번치→번들 잠금 안에서 실제 제목과 현재 참여자 코멘트를 현재 서버의 시작 시점
  사전으로 재검사한다.
  거부는 일반 BUNDLE_PUBLISH_BLOCKED 대신 COMMON_003이다. 기존 발행 멱등성은 유지한다.
- 초안 조회는 저장된 검사 상태가 아닌 현재 서버의 시작 시점 사전으로 실제 제목과 현재 참여자
  코멘트의 검사 상태·publishBlockers를 계산한다. 이 금칙어 계산은 DB 상태·revision·제목/코멘트
  버전·updatedAt·사용자 활동·알림을 변경하지 않는다. 기존 미초기화 제목 CRDT 복구는 유지한다.
- 금칙어 전용 스케줄러·DB 초안 스캔·백필과 별도 금칙어 이벤트는 제공하지 않는다.
- 재접속은 기존 상세 스냅샷으로 복구한다. 서버의 실시간 전달 범위는 기존 STOMP 구성을 따른다.
  발행본 snapshot의 profanity는 null이며 소급 검사 상태를 만들지 않는다. 마이그레이션의 boolean
  기본값 false나 저장된 dictionary version만으로 정상 판정하지 않는다.

스키마는 V44 → V45 → V46 → V47 순서로 적용한다. 적용된 `V46__bundle_profanity.sql`은
수정하지 않고, `V47__drop_bundle_profanity_recheck_index.sql`에서 사용하지 않는 재검사 인덱스를
삭제한다.

## 검증 기준

NFC/NFD·영문 대소문자·공백/점/제로폭 우회·자모·특수문자 전용 항목·추가/제외 우선순위,
기동 시 로딩 실패·실행 중 사전 불변·재시작 후 파일 변경 반영,
전체 최종 저장 경로의 다중 필드 오류·원자적 롤백·멱등 재시도,
초안 허용·CRDT·두 연결 상태 전파·재접속·참여자 제거·조회 시 현재 사전 반영과 무변경·
실제 편집의 상태 저장·기존 이벤트 전파·발행 동시성을 자동 검증한다.
소개 사전 검증은 인증·가입 완료 제한, JSON/내용 오류 구분, trim·grapheme 경계·줄바꿈,
금칙어의 introduction 필드 오류·단어 비노출, DB 무변경·요청 키 없이 성공을 검증 기준으로 둔다.
실제 iOS/WebView의 문구·버튼 연동은 별도 수동 검증이다. 테스트 프로필은 문맥 오탐으로 기존
fixture가 영향을 받지 않도록 작은 결정적 목록을 사용하며 실제 배포 목록은 별도 단위 테스트로 검증한다.
