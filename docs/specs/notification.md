# 알림·푸시 Spec

> #28 1차 상태 (2026-11-01): notifications 이관·가입 생산자 전환·목록/읽음/open과 알림 행의 활동 합산을 구현한다.
> 전체 21종 생산자·참여별 독촉 실행·기기/개인 설정/APNs 구현 완료를 뜻하지 않는다.
> 현재 연결 범위와 통합·출시 조건은 [1차 구현 경계](notification-foundation.md)를 따른다.
> 타 도메인의 `bunch*.md` 참조는 제공된 고정 승인 사본 기준이며 이 브랜치에 복제하지 않는다.

## 기준·범위·상태

2026-10-29 확정하고 2026-10-31 재대조한 번치 5장 원문 중 **5.12.1~5.12.3**과
번치·번들·소셜에서 발생하는 21종 알림의 공통 계약을 소유한다. 제품 요구사항 확정이며 구현 완료를 뜻하지 않는다.
원문의 번호·기능 ID·문구를 유지하고 참여 후 24·72시간 보완 등 이미 확정한 정책을 적용한다.

- 이 문서: 수신자·문구·목록·읽음·이동·중복 방지·활동 합산·리마인드·푸시 공통 정책.
- [알림 API](notification-api.md): 알림·읽음·개인 설정·기기·APNs 입출력과 오류·재시도.
- [알림 스키마](notification-schema.md): 알림·푸시 저장과 업무 트랜잭션 연결·전송 구조.
- 번치 Spec (`bunch.md`; 고정 승인 사본): 홈·역할·관계·이탈·재참여·삭제·접근 불가 안내. 알림은 업무의 접근·역할 판정을 재정의하지 않는다.
- [번들 Spec](bundle.md): 초안·참여·코멘트·발행의 실제 상태 변경. 알림 저장은 해당 업무 트랜잭션에서 연결한다.

## 5.12 알림

<a id="bunch-5-12-1"></a>
### 5.12.1 알림 목록 화면

기능 ID: `NOTI-01`.

번치 홈의 종에서만 진입한다. 피드·사진함·마이페이지에는 종을 두지 않는다.
뒤로가기·「알림」·「모두 읽음」 헤더 아래 현재 번치·현재 회원의 알림을 최신순으로 나열한다.
기기 푸시 권한이 꺼져 있으면 「알림 받기를 설정하고 유용한 알림을 받아보세요.」를 표시하고
탭 시 마이페이지 범위의 알림 설정으로 이동한다.

각 행은 제목·발생 시간·설명·안 읽음 빨간 점이다. 현재 번치 접두사는 목록에서 덧붙이지 않는다.
상대 시간은 1분 미만 「방금 전」, 1시간 미만 「N분 전」, 24시간 미만 「N시간 전」,
7일 미만 「N일 전」, 이후 「M월 D일」이다.
알림 보관은 30일, 목록 표시는 최신 최대 100개다. 빈 상태는 빈 알림 화면을 보여주며 디자인은 별도 확정한다.

읽음은 개인별·번치별이다. 행 탭은 해당 알림만, 「모두 읽음」은 현재 번치의 해당 회원 알림 전체를 처리한다.
화면에 아직 표시되지 않은 보관 중 알림도 포함해 성공 후 미확인 수·빨간 점이 일치해야 한다.
모두 읽음은 실행한 한 UPDATE로 처리한다. 동시 활동 병합과는 알림 행의 DB 갱신 순서를 따른다.
그 뒤 저장된 새 알림·활동은 안 읽음으로 남으며 별도 조회 시점 토큰·순번은 만들지 않는다.
미확인 수는 표시 한도와 별개로 같은 30일 보관 범위에서 센다. 안 읽음이 없으면 모두 읽음을 비활성화한다.

다른 번치 수는 전환 시트 배지에서만 보이며 전환 후 목록도 바꾼다.
새 알림은 재진입·당겨 새로고침 때 갱신한다. 개인별 종류 설정은 **푸시에만** 적용하고 앱 내 알림은 유지한다.
목록 실패는 공통 토스트, 모두 읽음 실패는 같은 토스트 후 기존 읽음 상태를 유지한다.

푸시 권한 안내는 목록 맨 위에 두고 안 읽음 빨간 점은 발생 시간 옆에 표시한다.

<a id="bunch-5-12-2"></a>
### 5.12.2 알림 눌렀을 때 이동

기능 ID: `NOTI-01`.

앱 내 행 탭은 해당 알림을 읽음으로 바꾸고 종류별 화면으로 이동한다. 뒤로가기는 알림 목록이다.
서버는 이동 직전 대상 존재·현재 번치 소속·참여·공개 범위·차단 등 **현재 접근 권한**을 다시 검사한다.
알림의 발생 당시 이름·제목·설명은 스냅샷으로 유지하며 대상 이름이 바뀌어도 기존 문구를 고치지 않는다.
이동한 상세는 현재 데이터를 표시한다. 새 활동 합산은 아래에서 별도로 정한 한 알림의 집계 과정이다.

푸시 탭은 앱을 열고 같은 목적지로 이동한다. 다른 번치면 먼저 그 번치로 전환하고 마지막 사용 번치도 저장하되
전환 토스트는 생략한다. 푸시에서 연 화면의 뒤로가기는 해당 번치 홈이다.
역할 변경 알림으로 연 역할별 권한 안내는 번치 Spec 5.6.2 (`bunch.md#bunch-5-6-2`; 고정 승인 사본)의 진입 경로별 뒤로가기 규칙을 우선한다.
로그아웃 상태면 로그인 후 같은 목적지 검증을 다시 수행한다. 푸시 payload 자체를 접근 권한으로 사용하지 않는다.

초안 발행·삭제, 번들 삭제, 참여 제외 등으로 목적지를 볼 수 없으면 이동하지 않고
「삭제되었거나 볼 수 없는 내용이에요」를 표시하며 알림은 남긴다.
푸시의 번치가 삭제·내보내짐 상태면 접근 불가 안내를 따른다.
네트워크 이동 실패는 공통 토스트 후 목록 유지다. 대상 접근 실패가 이미 처리한 읽음을 되돌리지 않는다.

### 5.12.3 알림 종류·문구

기능 ID: `NOTI-02`, `NOTI-04`.

다음 21종은 원문의 제목·설명·수신 범위·이동 대상을 보존한다.
직접 행동으로 발생한 알림은 **행동한 본인을 제외**하고 발생 시점의 유효 소속을 확인한다.
예약 리마인드는 행동자가 없는 시스템 사건이므로 생성자를 포함한 미작성 참여자 본인에게도 보낸다.
일반 알림에서 이미 이탈한 회원은 제외하되, 내보내짐과 삭제는 이탈·삭제 직전 확보한 해당 수신자를 사용한다.
표의 중복 기준은 이벤트와 수신 회원을 함께 구분한다. 같은 업무·요청·전송 재시도로 새 알림을 만들지 않는다.

**보완·표현 규칙**

- 새 활동은 API 계약에 따라 같은 수신자·초안의 최초 알림부터 10분 동안 하나로 합친다.
  예: 「경진님 외 1명이 사진 7장을 추가했어요.」. 합산 대상 이벤트를 중복으로 세지 않으며
  최초 제목·발생 시각은 유지하고 설명을 갱신하며 이미 읽은 수신자에게 새 활동이 오면 안 읽음으로 바꾼다.
  앱 내 행은 즉시 반영하고 푸시는 창 종료 시 한 번 보낸다. 창 종료 후 활동은 새 행이다.
  같은 집계라는 이유로 수신자에게 자기 활동을 보내지 않는다.
- **리마인드의 승인된 원문 예외:** 생성 후 일괄 24·72시간 대신 각 참여자의 참여 후 24·72시간에 최대 2회다.
  최초 참여자는 초안 생성 시점, 나중 참여자는 추가 시점부터 계산한다.
  작성 완료·참여 제외·번치 이탈·발행·초안 삭제 시 미전송 리마인드를 취소하고 실행 직전 다시 검사한다.
- 직접 행동 알림에는 행동 본인을 넣지 않는다. 예약 리마인드는 위 예외를 따른다. 실행 멤버 정보는 외부 번치 행동 알림에 표시하지 않는다.
  닉네임을 설명에 표시하는 종류는 새 활동과 새 멤버 참여다. 본인에게 받은 역할 변경은 표의 대상자 규칙을 따른다.
- 차단 관계 관련 알림은 만들지 않는다. 좋아요·댓글은 다른 번치가 남겼을 때만 만들며 우리 번치의 자체 반응은 제외한다.
  기존 알림은 이동 시 현재 차단·권한을 검사한다.
- `{번들 제목}`이 비면 「제목 미정」이다. 발생 뒤 이름·제목 변경으로 기존 알림 문구를 다시 계산하지 않는다.
- 댓글 설명에는 전체 댓글에서 줄바꿈을 없앤 내용을 넣는다. 앱 목록은 최대 2줄·이후 「…」,
  푸시는 50자를 넘으면 앞 50자 뒤 「…」다. 앱 목록 표시 길이를 저장 댓글의 길이 제한으로 사용하지 않는다.
- 일반 푸시 제목은 「[{알림을 받는 번치 이름}] {표의 제목}」, 내용은 표의 설명이다.
  대괄호는 수신 번치명이며 행동 번치명이 아니다. OS가 앱 이름 BUNCH·시간을 붙인다.
  **14·15번은 이미 번치명을 포함하므로 접두사를 추가하지 않는다.** 앱 내 목록에도 일반 접두사를 추가하지 않는다.
- 알림을 만들지 않는 일: 사진함 업로드·삭제, 초안 삭제, 발행본 수정·삭제, 일반 프로필 변경,
  단계 하락, 팔로우 취소, 요청 거절, 차단·해제, 신고 처리 결과, 일반 나가기.
  초안 사진 추가의 새 활동과 공개 범위 변경의 16번은 위 일반 비알림 규칙의 명시적 예외다.
- 시간대에 따른 발송 제한은 두지 않는다. 푸시는 기기 OS 권한·개인 종류 설정을 따르며
  권한을 꺼도 일반 앱 내 알림은 생성한다. 14·15번에는 앱 내 알림을 대신 만들지 않는다.

**저장·전송 보장**

업무 변경과 알림·수신자·전송 대기 기록을 같은 DB 트랜잭션으로 저장하고 커밋 후 APNs를 호출한다.
푸시 실패가 프로필 저장·인계·이탈·삭제 성공을 취소하지 않는다. 삭제·내보내짐 수신 정보는 번치 cascade에 종속시키지 않는다.
일시 실패 재시도와 영구 실패 기기 토큰 해제를 구분하고 재시도 횟수·백오프·보관은 DB 계약에서 정의한다.
기기 등록·갱신·해제와 개인 종류 설정의 서버 계약을 함께 마련하되 설정 화면은 마이페이지 범위다.
APNs가 수락한 것과 실제 기기 표시·열람은 다르며 **중복 없는 최종 전달을 보장하지 않는다.**
업무 이벤트 중복 생성 방지와 외부 푸시 최종 전달 보장은 구분한다.
