# 추천 번들 계약

이 문서는 이슈 #67(추천 번들 사진 묶기와 저장 구조)의 계산 규칙을 고정한다. 선정·제목·재계산·만료·조회는 이후 이슈(#68~#73)가
이 문서를 확장한다. **와이어프레임과 기능명세서가 다르면 기능명세서를 따른다.**

## 기준 문서

기능명세서 사진함 4.2.7(함께 찍은 사진 묶기)을 따르고, 풀어 쓴 설명은 추천 번들 백엔드 가이드 4장을 참고한다.
가이드와 명세서가 다르면 명세서가 기준이다. 사진 저장은 [사진함 기반 계약](photo-foundation.md), 날짜 변경은
[사진 촬영 날짜 변경 계약](photo-date.md)을 따른다.

값은 확정(명세서 근거 표시), 제안(명세서가 정하지 않아 개발이 기본안으로 구현), 확정 대기로 나눠 적는다.

## 이름

| 말 | 뜻 |
| --- | --- |
| 추천 번들 | 사용자에게 보이는 이름. 번들 만들기 화면의 추천 번들 시트 카드 한 장 |
| 후보 | 코드와 DB가 쓰는 이름(`bundle_candidates`). 추천 번들 하나가 후보 하나다 |
| 사진 묶음 | 서버가 "같은 자리에서 함께 찍었다"고 보고 하나로 묶은 사진들(코드의 `PhotoCluster`). 화면에는 보이지 않는다 |
| 업로드 묶음 ID | 한 번에 올린 사진들이 가진 같은 ID(`photo_uploaders.upload_batch_id`) |

코드 패키지는 `com.bunch.recommendation`이다. Notion API 태그는 `Recommendation`이다.

## 사진 묶기 계산 (4.2.7)

데이터베이스와 시계에 의존하지 않는 순수 계산이다. 호출하는 쪽이 계산에 넣을 사진만 골라 넘긴다.

### 입력

| 값 | 설명 |
| --- | --- |
| 사진 ID | |
| 촬영 날짜 | 사용자가 날짜를 조정한 사진은 조정한 날짜(3.1.3 로직 1, 3.4.1). 시간대 없는 현지 값 그대로 쓴다 |
| 촬영 시각 | 없을 수 있다. **업로드 시각으로 대신하지 않는다**(4.2.7 로직 4) |
| 올린 멤버들 | 함께 올린 사진은 여러 명이다. 사진은 1장으로 세고 올린 멤버는 모두 센다(4.2.7 로직 2) |
| 업로드 묶음 ID들 | 목록으로 받는다. 날짜를 한 번에 조정한 묶음 ID(#66)는 저장되기 전까지 넣지 않으며, 목록이라 나중에 더해도 계산이 바뀌지 않는다 |

### 계산에 넣지 않는 사진 (호출하는 쪽이 제외, 4.2.7 로직 1·상세 1)

- 촬영 날짜를 모르는 사진(「촬영 날짜를 확인할 사진」, 3.1.5). 날짜를 맞추면 그때부터 들어간다.
- 작성 중인 번들(초안)에 들어간 사진, 이미 발행된 번들에 쓰인 사진.

### 출력

사진 묶음 목록이다. 묶음마다 사진 ID들(카드 순서 규칙대로 정렬), 시작 날짜, 끝 날짜(자정을 넘겨 이은 묶음만), 올린 멤버
집합, 정리 전 1차 조건 통과 여부를 가진다. 조건을 못 채운 묶음도 돌려준다. 이후 재계산이 분리·병합을 판단하려면 필요하다.

### 규칙

| 단계 | 규칙 | 근거 |
| --- | --- | --- |
| 1. 날짜별로 묶기 | 사진함 날짜 섹션과 같은 날짜 기준으로 같은 날 사진을 모은다 | 4.2.7 상세 1 |
| 2. 하루 나누기 | 촬영 시각이 있는 사진을 시간순으로 놓고, **사진 사이가 4시간 이상 비면** 그 사이에서 나눈다. 나눈 양쪽에 각각 3장 이상 있을 때만 나눈다. 공백이 여러 군데면 가장 긴 공백부터 본다. 시각 있는 사진이 하나도 없거나 나눌 공백이 없으면 하루를 한 묶음으로 본다 | 4.2.7 상세 2·예외 |
| 3. 자정 잇기 | 전날 밤 22시 이후 사진과 다음 날 새벽 3시 이전 사진의 간격이 2시간 이내면 이어서 한 묶음으로 본다. 묶음의 시작 날짜는 첫날, 끝 날짜는 다음 날이다 | 4.2.7 상세 3·예외 |
| 4. 시각 없는 사진 붙이기 | 아래 표 | 4.2.7 상세 4 |
| 5. 1차 조건 | 정리 전 장수로 6장 이상이고 올린 멤버가 2명 이상이면 통과로 표시한다 | 4.2.7 상세 5 |

시각 없는 사진 붙이기(그날 사진 묶음이 하나뿐이면 판단 없이 그 묶음에 붙인다):

| 순서 | 기준 |
| --- | --- |
| ① | 같은 업로드 묶음 ID에 시각 있는 사진이 있으면 그 사진이 가장 많이 속한 묶음. 같으면 ②로 |
| ② | 그 사진을 올린 멤버가 그날 **한 묶음에만** 사진을 올렸으면 그 묶음 |
| ③ | 그날 사진이 가장 많은 묶음. 사진 수가 같으면 촬영 시각이 가장 이른 묶음 |

### 최종 판정은 연사 정리 뒤

6장 기준은 연사를 정리한 뒤의 장수다(4.2.7 상세 5, 4.2.8 로직 4). 이 계산은 정리 전 장수의 1차 판정까지만 하고,
최종 판정은 사진 선정 이슈(#68)가 한다.

## 처음 기준 숫자

명세서가 "처음 기준이며 써 보면서 조정한다"고 한 값이다(4.2.7 로직 6). 코드는 한곳(`RecommendationSettings`)에 모은다.

| 값 | 기본 |
| --- | --- |
| 하루를 나누는 빈 시간 | 4시간 |
| 나눈 양쪽 최소 장수 | 3장 |
| 자정 잇기 시작 시각 / 끝 시각 / 간격 | 22:00 / 03:00 / 2시간 |
| 추천 최소 장수 / 올린 멤버 | 6장 / 2명 |

## 해석한 부분 (제안)

명세서가 정하지 않았거나 모호해서 개발이 정한 것이다. 테스트로 고정하고, 달라지면 이 표와 테스트를 함께 바꾼다.

| 항목 | 해석 |
| --- | --- |
| 자정 잇기의 단위 | 사진 하나하나가 아니라 **전날의 마지막 묶음과 다음 날의 첫 묶음**을 잇는다. 그 두 묶음 밖의 묶음은 합치지 않는다("이틀치 전체를 합치지 않는다"). 묶음 하나는 한 번만 이어서 최대 이틀을 넘지 않는다 |
| 자정 잇기의 간격 | 전날 마지막 묶음의 마지막 사진과 다음 날 첫 묶음의 첫 사진 사이의 시간이 2시간 이하(같으면 잇는다) |
| 공백 4시간 | 정확히 4시간이면 나눈다(「4시간 이상」) |
| 사진 장수 세기 | 나눌 때의 양쪽 장수는 시각 있는 사진만 센다. 시각 없는 사진은 나눈 뒤에 붙는다 |
| 시각 없는 사진 붙이기 ①이 같을 때 | ②와 ③은 같은 수로 겨룬 묶음들 안에서만 고른다 |
| 시각 없는 사진 붙이기 ② | 올린 멤버가 여럿이면 각 멤버가 "한 묶음에만 올린" 묶음을 모아, 하나로 정해질 때만 쓰고 아니면 ③으로 간다 |
| 시각 없는 사진 붙이기 ③의 장수 | 붙이기 전 시각 있는 사진 장수. 붙이는 순서에 결과가 달라지지 않게 한다 |
| 묶음 안 사진 순서 | 첫날 시각 순 → 첫날 시각 없는 사진 → 다음 날 시각 순 → 다음 날 시각 없는 사진(4.2.3 로직 1). 시각 없는 사진은 사진 ID 순(먼저 올린 사진이 앞) |

## 확정 대기

| 항목 | 기본안 | 확인 대상 |
| --- | --- | --- |
| **하루 나누기의 "앞뒤에 사진을 올린 멤버가 한 명도 겹치지 않음"**(4.2.7 상세 2)의 정의 | 끊는 지점의 앞쪽 사진 전체와 뒤쪽 사진 전체의 올린 멤버 집합이 겹치지 않을 때로 해석하려 함. **이번에는 구현하지 않고 4시간 공백만 적용**한다 | 기획 |
| 자정 잇기의 단위(위 해석 표) | 인접한 두 묶음을 잇는 안 | 기획 |

## 이 이슈에서 하지 않는 것

연사 정리와 카드 사진 선정(#68), 제목(#69), 재계산과 저장 흐름(#70), 30일 만료와 목록 정렬(#71), 조회 API(#72), 초안
연결(#73), 날짜 조정 묶음 ID 저장(#66). 후보 저장 구조는 이 문서에 이어서 적는다.

## 테스트 기준

- 하루 나누기: 4시간 공백에서 나눔, 3시간 59분은 안 나눔, 한쪽이 2장이면 안 나눔, 양쪽 3장이면 나눔, 오전 8장 + 저녁
  1장은 한 묶음, 꾸준히 찍으면 한 묶음, 가장 긴 공백부터 나눔, 시각 있는 사진이 없으면 하루가 한 묶음.
- 자정 잇기: 23:10~23:50 + 00:20~01:30은 한 묶음(시작 전날, 끝 다음 날), 간격 2시간은 잇고 2시간 1분은 안 잇고, 이틀치
  전체를 합치지 않으며, 한 묶음은 한 번만 잇는다.
- 시각 없는 사진 붙이기: 묶음이 하나면 그대로, ①②③과 동률 처리, 다른 날의 같은 업로드 묶음은 무시.
- 1차 조건: 5장 미만, 올린 멤버 1명, 6장·2명 경계.
- 함께 올린 사진은 1장으로 세고 올린 멤버를 모두 센다. 날짜가 다른 사진은 다른 묶음. 묶음 안 사진 순서. 빈 입력.
