# 사진함 목록 조회 계약

이 문서는 이슈 #35의 사진함 목록 조회 규칙과 API 계약을 고정한다. 사진함 화면(3.1.1~3.1.4)과 번들 만들기 화면(4.1.1)이
같은 목록을 쓴다. 날짜 미확인 목록·사진 상세(#36), 삭제(#39), 날짜 변경(#37)은 이 범위에 포함하지 않는다.

## 기준 문서

기능명세서는 사진함 3.1.1~3.1.4, 3.2.1, 3.6.1, 번들 만들기 4.1.1을 따른다. 영속성은
[사진함 기반 계약](photo-foundation.md), 사진 저장 규칙은 [사진함 업로드 계약](photo-box.md)을 따른다.
기능명세서에 없는 값은 "확정 대기"로 표시하고 기본안으로 구현한다.

## 요청

```text
GET /api/v1/bunches/{bunchId}/photos
```

| 항목 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `bunchId` (경로) | Long | O | 조회할 번치 |
| `memberId` | Long | 선택 | 이 멤버가 올린 사진만 조회한다. 없으면 전체 |
| `cursor` | String | 선택 | 이전 응답의 `nextCursor`. 없으면 첫 페이지 |
| `size` | Int | 선택 | 한 번에 가져올 장수. 기본 60, 1~100 |

- 인증이 필요하다. 가입을 완료한 그 번치의 ACTIVE 멤버만 조회할 수 있다(3.1.1).
- `size`의 기본값 60은 명세서의 예시이며 몇 장씩인지는 개발에서 정한다(3.1.3 로직 4). 최대 100은 개발 결정이다.
- `cursor`는 앱이 해석하지 않고 그대로 되돌려 보낸다.

## 응답

```json
{
  "success": true,
  "data": {
    "totalCount": 128,
    "photos": [
      {
        "photoId": 5021,
        "thumbnailUrl": "https://res.cloudinary.com/demo/image/upload/c_fill,w_300,h_300/photos/a.jpg",
        "capturedDate": "2026-10-19",
        "capturedTime": "21:40:12",
        "uploaderIds": [12, 15]
      }
    ],
    "nextCursor": "MjAyNi0xMC0xOXwyMTo0MDoxMnw1MDIx"
  },
  "error": null
}
```

| 항목 | 설명 |
| --- | --- |
| `totalCount` | **번치 전체** 사진 수. 멤버 필터·날짜 없는 사진·처리 상태와 무관하다. 1,000장이면 앱이 사진 올리기 시트를 열지 않는다(3.2.1) |
| `photos[].photoId` | 사진 ID |
| `photos[].thumbnailUrl` | 정사각형 썸네일 URL(#33의 `PhotoImageUrls`, 300px). NEW 같은 표시는 없다(3.1.4) |
| `photos[].capturedDate` | 촬영 날짜. 사용자가 조정한 사진은 조정한 날짜(3.1.3 로직 1). 앱이 날짜 섹션으로 묶는다 |
| `photos[].capturedTime` | 촬영 시각 또는 `null`(시각 없이 날짜만 있는 사진) |
| `photos[].uploaderIds` | 올린 멤버 ID 목록. 함께 올린 사진은 여러 명이며 올린 순서다. 칩의 선택 수를 앱이 계산한다(3.1.2 상세 5, 4.1.1) |
| `nextCursor` | 다음 페이지 시작 위치. 마지막 페이지면 `null` |

위치 정보는 내려주지 않는다(3.2.2 로직 3). 필터 칩에 쓰는 멤버 목록(닉네임, 프로필 이미지)은 이 응답에 없고
`GET /api/v1/bunches/{bunchId}/members`(#43)를 쓴다.

## 포함·정렬 규칙

| 규칙 | 내용 | 근거 |
| --- | --- | --- |
| 날짜 기준 | `capturedDate`. 사용자가 조정한 사진은 조정한 날짜 | 3.1.3 로직 1 |
| 날짜 없는 사진 | 목록에서 제외한다. 날짜 미확인 영역은 #36이 맡는다 | 3.1.3 로직 2, 3.1.5 |
| 처리 상태 | `READY` 사진만 내려준다. 새 사진은 저장 즉시 `READY`라서 처리 중인 사진은 생기지 않는다 | #30, 3.1.4 |
| 번들에 쓰인 사진 | 제외하지 않는다 | 4.1.1 로직 3 |
| 정렬 | 최신 날짜 먼저, 같은 날짜에서는 최근에 찍은 사진 먼저 | 3.1.3 상세 2 |
| 같은 날짜·시각 | 업로드 순(먼저 올린 사진이 앞, `photoId` 오름차순) | 3.1.3 로직 3, 방향은 확정 대기 |
| 시각 없는 사진 | 같은 날짜의 맨 뒤 | 확정 대기 |

날짜 섹션으로 묶지 않고 **정렬된 평면 목록**으로 내려준다(확정 대기). 한 날짜가 여러 페이지에 나뉘어 올 수 있으며
앱이 이어 붙인다.

## 멤버 필터

- `memberId`가 있으면 그 멤버가 올린 사진만 내려준다. 함께 올린 사진(여러 멤버가 같은 사진을 올려 한 장으로 합쳐진
  사진)은 올린 멤버 모두의 필터에서 보인다(3.1.2 상세 3, 로직 2).
- 필터를 걸어도 `uploaderIds`에는 그 사진을 올린 **모든** 멤버가 들어간다.
- 그 번치의 활성 멤버가 아닌 `memberId`는 400이다. 나간 멤버의 칩은 보이지 않아 정상 경로가 아니다(3.1.2).
- 나간 멤버가 올린 사진의 정리는 번치 이탈 정리(#38, 3.6.1)가 맡는다.

## 이어서 불러오기

- 정렬 키 `(capturedDate, capturedTime, photoId)` 기준의 커서 방식이다. 페이지 사이에 사진이 올라오거나 지워져도
  이미 받은 사진이 중복되거나 빠지지 않는다.
- 커서는 위치를 담은 불투명한 문자열이다. 해석할 수 없는 값은 400이다.
- 서버는 `size + 1`장을 읽어 다음 사진이 있으면 `nextCursor`를 만든다.
- 다른 멤버가 올리거나 지운 사진은 실시간으로 반영하지 않는다. 앱이 진입·복귀·새로고침 때 다시 부른다(3.1.1 로직 2).

## 오류

| 상태 | 코드 | 상황 |
| --- | --- | --- |
| 400 | `COMMON_001` | 해석할 수 없는 `cursor`, `size`가 1~100이 아님, 숫자가 아닌 값, 번치 멤버가 아닌 `memberId` |
| 401 | `AUTH_001` | 토큰 없음·만료·세션 없음 |
| 403 | `AUTH_015` | 가입이 끝나지 않음 |
| 403 | `AUTH_002` | 번치 멤버가 아님(나간 멤버 포함) |
| 404 | `RESOURCE_001` | 번치 없음 |

## 인덱스

별도 정렬 인덱스를 만들지 않는다. 번치당 사진은 최대 1,000장(3.2.1)이라 번치로 거른 뒤 정렬해도 부담이 없고,
번치로 거르는 것은 기존 인덱스 `(bunch_id, file_hash)`가 돕는다. 한도가 크게 늘거나 느려지면 그때
`(bunch_id, captured_date, captured_time, id)` 인덱스를 새 마이그레이션으로 추가한다.

## 확정 대기

| 항목 | 기본안 | 확인 대상 |
| --- | --- | --- |
| 응답 구조(날짜 섹션으로 묶을지, 평면 목록으로 내려주고 앱이 묶을지) | 평면 목록 | 앱 |
| 올린 멤버 정보의 모양, 번치 전체 사진 수를 목록 응답에 넣는지 | 멤버 ID 목록, `totalCount` 포함 | 앱 |
| 시각 없이 날짜만 있는 사진의 같은 날짜 안 위치 | 맨 뒤 | 기획 |
| 같은 날짜·시각일 때 업로드 순의 방향 | 먼저 올린 사진이 앞 | 기획 |

## 테스트 기준

- 정렬: 최신 날짜 먼저, 같은 날짜는 늦은 시각 먼저, 같은 시각은 먼저 올린 사진 먼저, 시각 없는 사진은 같은 날짜의 맨 뒤.
- 이어서 불러오기: 페이지 경계(같은 시각 여러 장, 시각 없는 사진, 날짜 경계)에서 빠지거나 중복되지 않음, 마지막 페이지
  `nextCursor`, 기본 `size`.
- 제외: 날짜 없는 사진, `READY`가 아닌 사진, 다른 번치의 사진.
- 멤버 필터: 함께 올린 사진이 올린 멤버 모두에게 보임, 번치 멤버가 아닌 `memberId`는 400.
- 응답: `totalCount`는 필터와 무관, `uploaderIds` 순서, 썸네일 URL, 정해진 항목만 포함.
- 권한·입력: 비멤버·가입 미완료·없는 번치·토큰 없음, 잘못된 `cursor`·`size`.
