# 피드 공통 접근 계약

기능 ID: FEED-01, FEED-06. 이슈 #87(A).

기준은 [6장 시트](https://docs.google.com/spreadsheets/d/1ScziF7WoYLHRiC_UYJBkKsi0jL6KKQJD2TNDzW1QGfU/edit?gid=294136194#gid=294136194)의
6.1.1·6.1.4·6.1.7·6.2.1과 2026-11-07 승인 보완 정책이다.
이 범위의 충돌은 기존 PRD·번들·번치 Spec보다 위 기준이 우선한다.
공통 서버 인터페이스와 DB 계약은 [feed-api](feed-api.md)를 따른다.

## 접근 판단

- ACTIVE 계정이면서 가입 완료인 사용자만 조회한다. 인증 세션은 기존 JWT 필터가 검증한다.
- 현재 번치는 클라이언트 입력을 받지 않고 기존 서버 선택 규칙인 ACTIVE 소속의
  `lastUsedAt DESC, id DESC`로 정한다. 요청 간 접근 판단이나 현재 번치를 캐시하지 않는다.
- 소속 0개도 공개 번치의 PUBLIC 발행 번들을 조회할 수 있다. 번치 명의 행동은
  `CURRENT_BUNCH_REQUIRED`로 거부한다. 가입 중·탈퇴 계정은 조회도 거부한다.
- 피드 후보에서는 사용자의 **모든 ACTIVE 소속 번치**를 제외한다. LEFT·REMOVED는 제외 근거가 아니다.
  상세에는 이 피드 전용 제외를 적용하지 않는다.
- 현재 번치의 상세는 PUBLIC·PRIVATE 발행 번들을 모두 허용한다. 현재가 아닌 소속 번치를
  외부 경로로 볼 때에는 기존 번치 프로필 계약대로 외부 규칙을 적용한다.
- 외부 상세·피드 후보는 PUBLIC 발행 번들만 허용한다. 공개 번치는 누구나,
  비공개 번치는 현재 번치의 APPROVED 팔로우가 있어야 허용한다. PENDING은 허용하지 않는다.
- 현재 번치와 콘텐츠 소유 번치의 양방향 차단, 기존 번치 프로필 신고,
  번치·번들 운영 숨김, 현재 번치의 콘텐츠 숨김을 매 요청 DB에서 확인한다.
  내부 상세도 운영 숨김·현재 번치 신고 숨김을 우회하지 않는다.
- 좋아요·댓글 등의 쓰기는 같은 상세 접근 검사를 재사용하고 유효한 현재 ACTIVE 소속을 요구한다.
  역할·작성자·신고 횟수·대상별 멱등성은 해당 기능이 추가 검증한다.
- 기존 접근 불가 안내와 공개 범위 오류를 유지한다. 숨김·삭제·비발행·멤버 전용 외부 접근은
  존재 여부를 구분해 노출하지 않는다. 양방향 차단은 기존 번치 프로필 불가 응답을 사용한다.

## 피드와 후속 기능의 경계

팔로잉 구간은 최근 14일의 APPROVED 팔로우 대상 PUBLIC 번들, 공개 구간은 공개 번치의
PUBLIC 번들 중 앞 구간 중복을 제외한다. 각 페이지도 최신 접근 조건을 DB 조회에 적용한다.
A의 후보 집합 검사는 페이지를 받은 뒤 필터링하는 용도로 사용하지 않는다.
커서·광고·카드 조립은 #95가 구현하며 이번 변경에는 feed HTTP API를 추가하지 않는다.

댓글은 개인 작성자와 작성 시 번치 배지를 표시하고 한 단계 답글을 허용한다.
작성자만 삭제하며 관리자도 남의 댓글을 삭제할 수 없다. 삭제 자리는 개수에 포함하고
차단·신고·운영 숨김은 개수에서 제외한다. 기존 `bundle_comments`는 참여자 코멘트다.
댓글·좋아요·신고·장소·광고 테이블과 해당 API는 후속 이슈가 소유한다.

## 운영·신고 비노출

V23의 `feed_content_hides`는 실제 조회에 적용되는 억제 기록이다.
운영 숨김은 DB에서만 관리하며 운영자 인증·HTTP API는 만들지 않는다.
신고 접수·심사·24시간 한도와 분리하여 같은 대상의 여러 신고가 하나의 비노출을 공유한다.
신고는 신고 번치에만 숨기며 다른 번치나 소속 0개 사용자에게 자동 제재하지 않는다.
기존 `bunch_profile_reports`는 별도 백필 없이 직접 조회한다.

## 검증 기준

전용 PostgreSQL·Redis에서 가입/계정 상태, 소속 0개, 서버 현재 번치, 전체 ACTIVE 소속 제외,
PUBLIC/PRIVATE·PENDING/APPROVED, 양방향 차단·프로필 신고, 운영/신고 숨김·해제·번치 전환,
실제 기존 상세/페이지 응답, 동시 비노출 중복과 롤백, V23 제약·JPA validate를 검증한다.
실제 iOS/WebView/APNs 수동 검증은 별도다.
