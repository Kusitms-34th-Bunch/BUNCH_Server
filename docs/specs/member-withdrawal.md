# 회원 탈퇴 계약 — 이슈 #111

기준은 마이 기능명세서 7.6.1~7.6.4(USER-07)이며, 나가기 5.8.1·관리자 넘기기 5.6.7(메인), 사진 3.6.1·4.3.2,
피드 6.1.3·6.2.2·6.2.4~6.2.7, 온보딩 1.1.1·1.2.5·2.6.2를 함께 따른다. 7.6.1(안내 화면)·7.6.2의 체크박스·7.6.3의
화면은 앱이 처리하며, 서버는 아래 확인·처리 API와 오류 계약만 정한다.

## 방식: 계정 행은 남기고 개인정보만 비운다

`members`는 발행 번들(`created_by`)·번들 코멘트·번들 사진·번치 생성자·소셜 댓글·팔로우·신고가 외래 키로 참조한다.
명세서도 업로드된 번들과 번들 속 사진·코멘트 표시는 남기라고 하므로 회원 행을 삭제할 수 없다. 그래서
`accountStatus`를 `WITHDRAWN`으로 바꾸고 아래를 비운다. 새 마이그레이션은 없다(`nickname`은 nullable, `WITHDRAWN`은 기존 값).

| 비우는 것 | 근거 |
| --- | --- |
| 닉네임·출생연도·성별·프로필 사진, 가입 지문, 프로필 수정 요청 키·지문 | 7.6.4 "계정 정보 삭제" |
| 소셜 로그인 연결(`external_identity`, 연결 시 이메일 포함) | 7.6.4, 1.2.5. 연결이 없으므로 같은 소셜로 다시 로그인하면 새 계정이 만들어진다 |
| 푸시 기기·푸시 job·알림 설정 | 7.6.4 "푸시 토큰 해제" |
| 수신 알림(인박스)·접근 불가 공지 | 계정과 함께 사라지는 개인 데이터(명세서에 직접 문구는 없음) |
| 모든 기기의 로그인 세션 | 7.6.4 |

보존하는 것은 약관 동의 이력(개인정보가 비워져 식별되지 않음)과 번치 단위 기록(좋아요, 팔로우, 신고)이다.

## API

기본 경로 `/api/v1`, 유효한 access JWT와 활성 세션, 가입 완료 계정을 요구한다(미가입 403 `AUTH_015`).

| 메서드·경로 | 요청 | 성공 data |
| --- | --- | --- |
| `GET /members/me/withdrawal/check` | 없음 | `{ownerBunches:[{bunchId,name,imageUrl,myMembershipId,membershipVersion}]}` |
| `POST /members/me/withdrawal` | 없음(`Idempotency-Key` 없음) | `null` |

- **확인(7.6.2):** 다른 멤버가 있는 번치 중 내가 메인 관리자인 번치만 준다. 공동 관리자 번치와 나 혼자인 번치는
  넘길 대상이 없으므로 제외한다. 「다음」을 누를 때마다 서버에서 다시 읽는다. 기존 `GET /bunches`에는 번치 멤버 수가
  없어 "혼자인 번치"를 구분할 수 없으므로 이 조회를 둔다.
- **관리자 넘기기(7.6.3):** 번치마다 기존 `POST /bunches/{id}/owner-transfer`(5.6.7과 같은 처리·알림)를 호출한다.
  넘길 멤버 목록은 기존 `GET /bunches/{id}/memberships`를 쓴다.
- **탈퇴:** 처리 직전에 같은 판단을 번치 잠금 아래 다시 한다(7.6.4 로직 1). 관리자 번치가 남아 있으면 아무것도 바꾸지 않고
  409 `USER_005`로 중단하며 `error.detail.bunches`에 그 번치 목록(`bunchId`,`name`,`imageUrl`,`myMembershipId`,
  `membershipVersion`)을 담는다. 앱은 7.6.3 안내 모달을 띄운다.
- 완료 뒤 재요청과 같은 토큰의 모든 요청은 401 `AUTH_001`이다(세션 삭제, 그리고 `WITHDRAWN` 계정은 모든 API가 거절).
  동시에 두 요청이 오면 회원 잠금으로 직렬화되어 하나만 처리하고 다른 하나는 401이다. 그래서 `Idempotency-Key`는
  재생할 결과가 없어 받지 않는다.

## 처리 순서(7.6.4 로직 2, 한 트랜잭션)

1. 회원 행을 잠그고, 소속 번치를 **ID 오름차순**으로 잠근 뒤 번치마다 다시 판단한다.
   - 내가 메인 관리자이고 다른 멤버가 있으면 전체 롤백 + 409
   - 내가 메인 관리자이고 혼자이면 번치를 삭제한다(기존 번치 삭제와 같은 처리)
   - 그 밖에는 번치를 나간다(5.8.1: 업로드 사진 삭제 3.6.1, 내가 만든 초안 삭제와 남의 초안의 참여·코멘트 제거 4.3.2,
     다른 멤버에게 알리지 않음)
2. 내 소셜 댓글·답글을 **삭제된 댓글과 같은 상태**로 만든다(내용을 비우고 삭제 시각을 기록). 그러면 6.2.7 로직 6대로
   회색 기본 이미지·「작성자」·「삭제된 댓글입니다」로 보이고 배지·작성 날짜·「답글 N」이 숨겨지며 달린 답글은 남는다.
3. 발행 번들 속 내 코멘트의 원문을 비운다. 표시는 「작성자」·기본 이미지·「삭제된 코멘트입니다」(6.2.5)이다.
4. 푸시 기기·job·알림 설정, 수신 알림·접근 공지, 요청 기록을 삭제하고 소셜 연결을 삭제한다.
5. 개인정보를 비우고 `WITHDRAWN`으로 바꾼다. 프로필 이미지 파일은 커밋 뒤에 삭제한다.
6. **커밋 뒤에** 모든 기기의 세션을 삭제한다. DB 처리가 실패하면 롤백되고 세션은 그대로여서 로그아웃되지 않는다.
   세션 삭제 자체가 실패해도 `WITHDRAWN` 계정은 모든 API에서 401이므로 남은 세션은 쓸 수 없다.

잠금 순서는 회원 → 번치 ID 오름차순 → 번들·사진 순서다. 좋아요는 번치 단위(6.2.6)라 지우지 않는다. 탈퇴를 다른 멤버에게
알리지 않는다(5.8.1). 실패하면 계정은 그대로이고(전체 롤백) 앱은 7.6.4의 오류 토스트를 보인다. 요청 중 앱이 종료되어도
서버는 끝까지 처리한다.

## 탈퇴 뒤 표시와 집계

| 화면 | 규칙 |
| --- | --- |
| 발행 번들 코멘트 칩(6.2.5) | 기본 이미지 + 「작성자」, 내용 「삭제된 코멘트입니다」 |
| 참여 멤버·픽(6.1.3, 6.2.2, 6.2.4) | 빼지 않고 기본 이미지로 보이며 「외 N명」에도 센다 |
| 댓글·답글(6.2.7) | 삭제된 댓글과 같은 모양. 댓글 수·「답글 N」은 삭제된 것을 포함해 그대로 |
| 초대 카드(2.6.2) | 초대한 사람이 탈퇴했으면 From을 숨긴다 |
| 로그인(1.2.5) | 같은 소셜 계정은 새 계정으로 가입한다. 이전 기록과 연결하지 않는다 |

## 명세서가 정하지 않아 정한 것

- 푸시 job은 취소가 아니라 삭제한다(전송 worker는 사라진 job을 건너뛴다).
- 수신 알림·접근 공지는 30일 자동 삭제를 기다리지 않고 탈퇴할 때 지운다.
- 소셜 댓글·발행 번들 코멘트는 표시만 숨기지 않고 원문을 지운다(PRD "원래 내용은 삭제", 복구할 수 없다는 7.6.1 안내).
- 모든 세션 삭제는 Redis 키 `session:*`를 `SCAN`으로 훑어 해당 회원의 값만 지운다. 탈퇴는 드문 요청이라 허용하며,
  세션 수가 매우 많아지면 회원별 색인으로 바꾼다.

## 문서 충돌 정리

명세서(마이 7.6, 피드 6.2.7 로직 6)를 따르도록 PRD USER-07·MEMBER-12와 번들·번치 Spec의 이전 문구를 바꿨다.

| 이전 | 기준 |
| --- | --- |
| 작성자 "탈퇴한 멤버", 코멘트 "탈퇴한 멤버가 쓴 코멘트예요" | 「작성자」, 「삭제된 코멘트입니다」 |
| 탈퇴 시 메인 관리자 자동 승계(기여 횟수·최근 활동·가입일·ID 순) | 권한을 직접 넘겨야 하며 남아 있으면 탈퇴 중단(7.6.3·7.6.4) |
| 혼자인 번치 목록과 "함께 영구 삭제돼요" 안내 | 따로 안내하지 않고 함께 삭제(7.6.2·7.6.3) |

## 검증 기준

실제 PostgreSQL·Redis로 개인정보 삭제와 같은 소셜 재가입의 새 계정, 일반 멤버·공동 관리자의 나가기와 알림 없음, 관리자 번치
중단과 번치 목록·상태 불변, 혼자인 번치 삭제, 권한을 넘긴 뒤 탈퇴, 중간 실패 시 전체 롤백과 세션 유지, 모든 기기 세션 삭제,
기기·설정·알림·공지 정리와 타인 데이터 보존, 사진·초안·번들 코멘트·소셜 댓글 처리와 집계 유지, 동시 요청, 미가입·탈퇴
계정의 거절, 탈퇴 계정의 프로필 수정·알림 설정·문의 채널·약관 원문 API 거절을 확인한다.
