# 개발 규칙

## 프로젝트 구조

- Kotlin 1.9.25, Spring Boot 3.5.4, JDK 21과 루트 단일 Gradle 모듈을 사용한다.
- 기본 패키지는 `com.bunch`, 공통 처리는 `global`에 둔다.
- 필요한 패키지만 만들고 기존 패턴을 우선 사용한다.

## 필수 완료 조건

| 조건 | 이유 | 검증 / 실패 기준 |
| --- | --- | --- |
| 관련 테스트·build 성공 | 회귀 방지 | 실제 DB·Redis에서 clean build, 실패 시 미완료 |
| API·데이터 계약 갱신 | 클라이언트·DB 호환성 | 기능 추가 시 관련 Spec·테스트·새 마이그레이션, 불일치 시 미완료 |
| 비밀값 제외 | 자격 증명 보호 | staged diff에 실제 비밀값·원문 토큰이 있으면 미완료 |
| 검증 한계 기록 | 완료 주장 정확성 | 실행·미실행·결과·이유 누락 시 미완료 |

스키마 변경은 새 Flyway 마이그레이션으로 관리하고 JPA `ddl-auto: validate`를 유지한다.
적용한 마이그레이션은 수정하지 않는다. 정리 전 계획과 회귀 테스트를 확보한다.
운영에서 Swagger는 기본 비활성화하며 새 의존성·미정 정책을 임의 추가하지 않는다.

## 검증

README에 따라 PostgreSQL·Redis와 테스트 DB를 준비한다.

```bash
DB_URL=jdbc:postgresql://localhost:5432/bunch_test ./gradlew clean build
```

통합 테스트는 `test` 프로필을 사용한다. 구성되지 않은 린트·정적 검사를
실행했다고 보고하지 않는다. 실행 결과는 PR과 완료 보고에 남긴다.

## 권장 사항

작은 diff, 삭제와 재사용, 필요한 범위의 추상화를 우선한다.
